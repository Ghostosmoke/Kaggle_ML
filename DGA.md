# 🛡️ DGA Domain Detection — РАЗБОР ВСЕХ БЛОКОВ (dga-v2 (1).ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** Отличить легитимные домены от сгенерированных вирусами (DGA — Domain Generation Algorithm). Вирусы создают случайные имена (например, `xqz7k2m.com`), чтобы обойти блокировки.  
**Зачем это нужно на практике:** Это классическая задача кибербезопасности. Нужно максимизировать точность обнаружения вредоносных доменов, минимизируя ложные срабатывания на нормальные сайты.  
**Ключевая метрика:** `F-0.5 Score ≈ 0.91`. В F-0.5 точность (precision) весит в 2 раза больше, чем полнота (recall). Это значит, что решение настроено на минимум ложных блокировок легитимных сайтов.  
**Логика пайплайна:** Загрузили миллионы доменов → из каждого извлекли 28 статистико-лингвистических признаков → обучили градиентный бустинг (CatBoost) на CPU → предсказали классы для теста → сохранили `submission.csv`.

### 🔹 БЛОК 1: Импорт библиотек + конфигурация
🎯 **Задача блока:** Подключить инструменты, зафиксировать случайность и задать параметры обучения.  
📁 **Файлы/Данные:** Пока не загружаются. Готовятся словари и константы.  
🛠 **Библиотеки:** 
- `pandas` / `numpy` — чтение CSV и быстрые матричные операции.
- `catboost` — реализация градиентного бустинга. Внутри строит деревья, умеет работать с категориальными признаками без one-hot encoding и устойчив к переобучению.
- `sklearn.metrics` (`fbeta_score`, `accuracy_score` и др.) — считают качество предсказаний. `fbeta_score(beta=0.5)` штрафует за ложные срабатывания строже, чем за пропуски.
- `tqdm` — рисует прогресс-бар в консоли. Внутри считает итерации и обновляет строку вывода через `\r`.
- `warnings.filterwarnings('ignore')` — глушит технические предупреждения sklearn/catboost, чтобы логи не перегружались.  
🔄 **Что происходит с данными:** Задаётся `RANDOM_STATE=42` для воспроизводимости. Определяется словарь `ENGLISH_FREQ` с частотой букв в английском языке — он станет базой для сравнения «человеческого» и «случайного» текста.  
🔜 **Переход:** Конфиг готов, переходим к написанию функций, которые будут «разбирать» домены на числа.

### 🔹 БЛОК 2: Функции извлечения признаков (Feature Engineering)
🎯 **Задача блока:** Превратить строку домена в вектор из 28 числовых характеристик.  
📁 **Файлы/Данные:** На вход подаётся одна строка домена (например, `"example.com"`).  
🛠 **Библиотеки:** 
- `math.log2` — нужна для формулы энтропии Шеннона.
- Встроенные `set`, `sum`, `re`-логика — для подсчёта символов без внешних зависимостей.  
🔄 **Что происходит с данными:** Функция `extract_advanced_features()` делает следующее:
1. **Очистка:** Убирает `http://`, `www.`, оставляет только имя домена и TLD.
2. **Базовая статистика:** Длина имени, длина зоны, доля цифр/букв/спецсимволов.
3. **Лингвистика:** Считает гласные/согласные, ищет длинные цепочки согласных (признак генерации), считает кластеры гласных.
4. **Энтропия Шеннона:** `H = -Σ(p * log2(p))`. Чем выше энтропия, тем «случайнее» строка. DGA-домены обычно имеют энтропию > 3.5.
5. **Хи-квадрат:** Сравнивает распределение букв в домене с `ENGLISH_FREQ`. Формула: `Σ((наблюдаемое - ожидаемое)² / ожидаемое)`. Большое значение = текст не похож на английский.
6. **N-граммы:** Считает долю уникальных биграмм/триграмм и редких комбинаций.
7. **Сборка:** Все 28 признаков упаковываются в `np.array(dtype=np.float32)`.  
🔜 **Переход:** Функции готовы. Теперь нужно прогнать через них миллионы строк из файлов.

### 🔹 БЛОК 3: Загрузка данных и массовая векторизация
🎯 **Задача блока:** Прочитать train/test CSV и превратить каждый домен в вектор из 28 чисел.  
📁 **Файлы/Данные:** 
- `train.csv` (17.7M строк, колонки: `domain`, `label`)
- `test.csv` (7.6M строк, колонки: `id`, `domain`)
- `web.txt` (словарь популярных доменов — в логе не найден, скрипт продолжает работу без него)  
🛠 **Библиотеки:** 
- `pd.read_csv()` — читает файлы построчно, экономя RAM.
- `tqdm()` — обёртка вокруг цикла, показывает скорость обработки (~19k строк/сек).
- `gc.collect()` — принудительно вызывает сборщик мусора Python, освобождая оперативную память после удаления больших датафреймов.  
🔄 **Что происходит с данными:** 
1. Загружается train. Пропуски в `domain` заполняются пустыми строками.
2. Запускается цикл по `train['domain']`. Для каждого домена вызывается `extract_advanced_features()`. Результат складывается в `X_train` (матрица 17.7M × 28).
3. `train` удаляется через `del train`, вызывается `gc.collect()` для очистки RAM.
4. Аналогично обрабатывается test → получается `X_test` (7.6M × 28).  
🔜 **Переход:** Данные превращены в чистые числовые матрицы. Готовимся к обучению.

---

### 🔹 БЛОК 4: Разделение на train/val и настройка CatBoost
🎯 **Задача блока:** Разбить обучающую выборку для валидации и задать гиперпараметры модели.  
📁 **Файлы/Данные:** `X_train` (28 признаков), `y_train` (метки 0/1).  
🛠 **Библиотеки:** 
- `train_test_split(..., stratify=y_train)` — делит данные 80/20, сохраняя пропорцию классов 0 и 1 в обеих частях. Это важно, чтобы валидация была репрезентативной.
- `CatBoostClassifier` — модель градиентного бустинга.  
🔄 **Что происходит с данными:** 
1. Считается баланс классов: ~7.8M нулей и ~6.3M единиц. Дисбаланс 1.25:1.
2. Вычисляется `scale_pos_weight = 1.248`. CatBoost использует его внутри, чтобы больше штрафовать ошибки на миноритарном классе.
3. Задаются параметры: `iterations=1500`, `learning_rate=0.1`, `depth=6`, `task_type='CPU'`, `eval_metric='AUC'`, `early_stopping_rounds=150`. Модель остановится раньше, если 150 итераций подряд не будет улучшения на валидации.  
🔜 **Переход:** Параметры зафиксированы, запускаем тренировку.

---

### 🔹 БЛОК 5: Обучение модели и валидация
🎯 **Задача блока:** Обучить CatBoost на тренировочной части, проверить на валидационной, проанализировать качество.  
📁 **Файлы/Данные:** `X_tr`, `y_tr` (обучение), `X_val`, `y_val` (проверка).  
🛠 **Библиотеки:** 
- `model.fit(eval_set=(X_val, y_val))` — CatBoost параллельно обучается на train и считает метрику на val. Внутри использует упорядоченный бустинг (Ordered Boosting) для борьбы с переобучением.
- `classification_report`, `confusion_matrix` — выводят точность, полноту, F1 и матрицу ошибок.  
🔄 **Что происходит с данными:** 
1. Запускается 1500 итераций. Лог показывает рост AUC с 0.909 до 0.977 за ~1 час 4 минут.
2. Early stopping не срабатывает (метрика растёт до конца).
3. На валидации получаем: `Accuracy: 92.32%`, `F-0.5 Score: 0.9150` (цель достигнута).
4. Выводится важность признаков: топ-3 — `length`, `chi_square`, `max_consonant_streak`. Это подтверждает, что модель опирается на длину домена, отклонение от английского языка и неестественные цепочки согласных.  
🔜 **Переход:** Модель обучена и проверена. Делаем финальные предсказания на тесте.

### 🔹 БЛОК 6: Финальный прогноз и сохранение submission
🎯 **Задача блока:** Применить модель к `X_test` и оформить ответ для Kaggle.  
📁 **Файлы/Данные:** `X_test` (7.6M строк), `submission.csv` (выходной файл).  
🛠 **Библиотеки:**

- `pd.DataFrame().to_csv(index=False)` — сохраняет без лишнего столбца индексов.  
🔄 **Что происходит с данными:** 
1. Модель предсказывает 0 или 1 для каждого из 7.6M доменов.
2. Распределение: ~4.23M чистых, ~3.36M DGA.
3. Формируется датафрейм с колонками `id`, `label` и сохраняется в `submission.csv`.  
🔜 **Переход:** Работа завершена, файл готов к отправке.
