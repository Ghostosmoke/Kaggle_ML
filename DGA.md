# 🛡️ DGA Domain Detection — РАЗБОР ВСЕХ БЛОКОВ (dga-v2 (1).ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** Отличить легитимные домены от сгенерированных вирусами (DGA — Domain Generation Algorithm). Вирусы создают случайные имена (например, `xqz7k2m.com`), чтобы обойти блокировки.  
**Зачем это нужно на практике:** Это классическая задача кибербезопасности. Нужно максимизировать точность обнаружения вредоносных доменов, минимизируя ложные срабатывания на нормальные сайты.  
**Ключевая метрика:** `F-0.5 Score ≈ 0.91`. В F-0.5 точность (precision) весит в 2 раза больше, чем полнота (recall). Это значит, что решение настроено на минимум ложных блокировок легитимных сайтов.  
**Логика пайплайна:** Загрузили миллионы доменов → из каждого извлекли 28 статистико-лингвистических признаков → обучили градиентный бустинг (CatBoost) на CPU → предсказали классы для теста → сохранили `submission.csv`.

### 🔹 БЛОК 2: Функции извлечения признаков (Feature Engineering)
🎯 **Задача блока:** Превратить строку домена в вектор из 28 числовых характеристик.  
📁 **Файлы/Данные:** На вход подаётся одна строка домена (например, `"example.com"`).  
🛠 **Библиотеки:** 
- `math.log2` — нужна для формулы энтропии Шеннона.
- Встроенные `set`, `sum`, `re`-логика — для подсчёта символов без внешних зависимостей.  
🔄 **Что происходит с данными:** Функция `extract_advanced_features()` делает следующее:
1. **Очистка:** Убирает `http://`, `www.`, оставляет только имя домена и TLD.
2. **Базовая статистика:** Длина имени, длина зоны, доля цифр/букв/спецсимволов.
3. **Лингвистика:** Считает гласные/согласные, ищет длинные цепочки согласных (признак генерации), считает кластеры гласных.
4. **Энтропия Шеннона:** `H = -Σ(p * log2(p))`. Чем выше энтропия, тем «случайнее» строка. DGA-домены обычно имеют энтропию > 3.5.
5. **Хи-квадрат:** Сравнивает распределение букв в домене с `ENGLISH_FREQ`. Формула: `Σ((наблюдаемое - ожидаемое)² / ожидаемое)`. Большое значение = текст не похож на английский.
6. **N-граммы:** Считает долю уникальных биграмм/триграмм и редких комбинаций.
7. **Сборка:** Все 28 признаков упаковываются в `np.array(dtype=np.float32)`.  
🔜 **Переход:** Функции готовы. Теперь нужно прогнать через них миллионы строк из файлов.

- `gc.collect()` — принудительно вызывает сборщик мусора Python, освобождая оперативную память после удаления больших датафреймов.

4. Аналогично обрабатывается test → получается `X_test` (7.6M × 28).

### 🎯 ОБЩАЯ ЦЕЛЬ & АРХИТЕКТУРА
**Задача:** Классифицировать доменные имена как DGA-генерированные (`1`) или легитимные (`0`).  
**Ключевая особенность:** Отказ от символьной векторизации в пользу **28 инженерных признаков**, рассчитанных вручную: энтропия, χ²-тест, редкие n-граммы, кластеры согласных/гласных, позиции цифр, популярность TLD.  
**Метрика:** `F-0.5` (β=0.5). В SOC-системах это критично: штраф за False Positive в 4× выше, чем за False Negative. Аналитики не хотят получать тысячи ложных алертов на легитимные CDN-домены.  
**Пайплайн:** Загрузка CSV → Векторизация признаков в `numpy` → Stratified 80/20 сплит → CatBoost (CPU) → Валидация по F-0.5 → Feature Importance → Inference → `submission.csv`.

### 🔹 РАЗБОР ПО ЭТАПАМ ВЫПОЛНЕНИЯ

#### 🔹 ЭТАП 1: Конфигурация & `ENGLISH_FREQ`
- Фиксирует `RANDOM_STATE=42`, `BETA=0.5`, `TEST_SIZE=0.2`.
- Словарь `ENGLISH_FREQ` — эталонные частоты букв в английском языке. Используется для χ²-теста: DGA-домены генерируют символы равномерно, что даёт высокий χ²-скор при сравнении с реальным распределением.

#### 🔹 ЭТАП 2: Функции извлечения признаков (`extract_advanced_features`)
Чистый Python + `math` + `collections`. Рассчитывает 28 числовых индикаторов:
1. **Базовые:** длина домена, TLD, кол-во цифр/букв/спецсимволов, их доли.
2. **Фонетические:** `vowel_ratio`, `consonant_ratio`, `vc_ratio`, `max_consonant_streak`, `max_vowel_cluster`. DGA часто генерирует непроизносимые цепочки (`xkq7rzp`).
3. **Статистические:** 
   - `entropy` (Shannon) → мера случайности.
   - `chi_square` → отклонение от английского распределения.
   - `rare_bigram_ratio`, `rare_trigram_ratio` → доля уникальных пар/троек символов.
4. **Позиционные:** `starts_with_digit`, `ends_with_digit`, `max_consecutive` (повторы `aaaa`).
5. **Контекстные:** `is_popular_tld`, `is_popular` (проверка по white-list), `unique_chars`, `char_density`.

#### 🔹 ЭТАП 3: Загрузка данных & `tqdm`
- `pd.read_csv` читает ~17.7M строк. `domain` кастится в `str`, `fillna('')`.
- `extract_advanced_features` вызывается в list comprehension с `tqdm`. **Время:** ~15 мин на train, ~7.5 мин на test. Чистые Python-циклы, но работают стабильно.

#### 🔹 ЭТАП 4: Сплит & `scale_pos_weight`
- `train_test_split(..., stratify=y)` сохраняет пропорцию классов `0:1 ≈ 1.248:1`.
- `scale_pos_weight = n_neg / n_pos ≈ 1.248`. CatBoost умножает градиенты миноритарного класса на это значение, компенсируя дисбаланс на уровне функции потерь.

#### 🔹 ЭТАП 5: CatBoost Training (CPU)
- `iterations=1500`, `learning_rate=0.1`, `depth=6`, `loss_function='Logloss'`, `eval_metric='AUC'`.
- `early_stopping_rounds=150`, `use_best_model=True` → модель откатывается к итерации с лучшим AUC на validation.
- `thread_count=-1` → задействует все ядра CPU.
- **Лог обучения:** 1500 итераций за ~1h 4m. `bestTest=0.977459` (AUC).

#### 🔹 ЭТАП 6: Валидация & Feature Importance
- `fbeta_score(y_val, y_val_pred, beta=0.5) = 0.9150`.
- Топ-5 признаков по важности: `chi_square` (16.15), `length` (18.17), `max_consonant_streak` (11.57), `tld_length` (10.31), `special_chars` (7.53).
- Confusion Matrix показывает сбалансированные ошибки (~131k FP, ~140k FN на 3.5M val-строках).

#### 🔹 ЭТАП 7: Inference & Submission
- `model.predict(X_test)` → `~4.23M (0)`, `~3.36M (1)`.
- Сохранение `submission.csv`. Пайплайн завершён.

### 🧠 ВНУТРЕННЯЯ МЕХАНИКА БИБЛИОТЕК (DEEP DIVE)

#### 🔹 `catboost.CatBoostClassifier`
| Компонент | Внутренняя механика | Почему это важно в проекте |
|:---|:---|:---|
| **Ordered Boosting** | Вместо стандартного GBDT вычисляет остаток для каждого объекта, используя подмножества, исключающие его же лейбл. Убирает **prediction shift** (переобучение на шумных объектах). | На 25M строках стандартный бустинг быстро запоминает редкие артефакты логов. Ordered Boosting даёт стабильную калибровку вероятностей. |
| **Symmetric Trees (Oblivious)** | Все листья на одной глубине делятся по **одному и тому же признаку**. Ускоряет inference в 5–10×, снижает дисперсию. `depth=6` → 64 листа. | Критично для CPU-режима. Глубина 6 + симметричность даёт оптимальный trade-off между качеством и временем обучения. |
| `scale_pos_weight` | Модифицирует гессиан и градиент для класса `1`: `g_new = g * w`, `h_new = h * w`. Эквивалентно взвешиванию лог-лосса. | Компенсирует дисбаланс 1.25:1 без необходимости семплирования. |
| `eval_metric='AUC'` + `early_stopping` | Мониторит ROC-AUC на validation каждые 50 итераций. Если 150 шагов нет улучшения → стоп. `use_best_model=True` откатывает веса. | Предотвращает переобучение после ~1200 итерации. AUC выбран т.к. не зависит от порога, в отличие от F1. |
| `task_type='CPU'` | Использует многопоточную C++-реализацию с lock-free обновлением гистограмм признаков. `thread_count=-1` → `num_cores`. | На Kaggle-инстансах (2–4 ядра) это единственный стабильный вариант. GPU-режим требовал бы `gpu_ram_part` и мог упасть по OOM. |

#### 🔹 Математика Feature Engineering
| Признак | Формула / Алгоритм | Физический смысл для DGA |
|:---|:---|:---|
| **Shannon Entropy** | `H = -Σ p(c)·log₂(p(c))`, `p(c)=count/len` | DGA → равномерное распределение → `H≈3.5-4.5`. Легитимные → `H≈2.0-3.0`. |
| **Chi-Square** | `χ² = Σ ((O_i - E_i)² / E_i)`, `E_i = ENGLISH_FREQ[c]·len` | Меряет отклонение от английских частот. DGA игнорирует лингвистику → `χ²` высокий. |
| **Rare N-gram Ratio** | `rare = count(bigrams where freq==1) / total_bigrams` | Случайные строки порождают много уникальных пар. Легитимные домены повторяют морфемы (`cloud`, `net`, `api`). |
| **Max Consonant Streak** | Линейный проход, счётчик непрерывных согласных | DGA генерирует `xkqzrtp` → streak ≥4. Английский редко >3 (`strength` = исключение). |

#### 🔹 `sklearn.model_selection.train_test_split`
- **Stratify:** Алгоритм группирует индексы по классам, затем равномерно распределяет их по train/test, сохраняя `n_pos/n_neg`. Без этого в test могло бы попасть <1% malware, что исказило бы F-0.5.
- **Random State:** Фиксирует `np.random.permutation`. Гарантирует воспроизводимость сплита при перезапусках.

#### 🔹 `sklearn.metrics.fbeta_score`
- `Fβ = (1+β²)·(P·R) / (β²·P + R)`. При `β=0.5` → `F0.5 = 1.25·(P·R) / (0.25·P + R)`. Precision получает вес `4×` относительно Recall.
- **Внутренняя механика:** Считает `TP, FP, FN` через `y_true` и `y_pred`, затем применяет формулу. `zero_division` обрабатывает деление на 0.

#### 🔹 `gc.collect()` & `tqdm`
- `gc.collect()`: Принудительно запускает сборщик мусора Python. После создания `(17719790, 28)` массива (~1.9 ГБ) освобождает pandas-фреймы и временные объекты. Без этого RAM мог уйти в своп.
- `tqdm`: Использует `sys.stderr` и ANSI-escape коды для отрисовки прогресс-бара. `desc='Train'` добавляет префикс. Обновление каждые `mininterval=0.1s` не блокирует GIL.

#### 🔹 `numpy.float32` & Память
- `np.array(features, dtype=np.float32)` → 4 байта/признак. `(17.7M × 28) × 4B ≈ 1.98 ГБ`. В `float64` было бы ~3.96 ГБ.
- CatBoost internally кастит в `float32` при построении гистограмм. Явное указание экономит 2× RAM и ускоряет копирование в C++-память.

### ⚠️ КРИТИЧЕСКИЕ НЮАНСЫ & ТОЧКИ РОСТА

1. **Чистые Python-циклы в `extract_advanced_features`**  
   25M вызовов функции с `re`, `Counter`, `set` внутри. Время: ~23 мин.  
   ✅ **Оптимизация:** Переписать на `pandas` векторизацию или `numba.njit`. Сократит время до ~2–3 мин.

2. **Отсутствие `cat_features` в CatBoost**  
   TLD и `is_popular` переданы как `float32`, хотя это категориальные признаки. CatBoost мог бы закодировать их целевым средним (Target Encoding) и дать +0.5–1.0% AUC.  
   ✅ **Фикс:** `cat_features=['is_popular_tld', 'is_popular']` + `one_hot_max_size=2`.

3. **Оптимизация по AUC, оценка по F-0.5**  
   Early Stopping смотрит на AUC, но финальная метрика — F-0.5. При сильном сдвиге распределения вероятностей порог `0.5` может быть неоптимальным.  
   ✅ **Улучшение:** Добавить `calibration_curve` или оптимизацию порога на validation, как в `bind-reverse`.

4. **Монолитная структура (один `main()`)**  
   Ноутбук скомпилирован в один скрипт. На Kaggle это нормально, но усложняет отладку.  
   ✅ **Рефакторинг:** Разбить на ячейки: `1. Load`, `2. Features`, `3. Train`, `4. Val`, `5. Predict`.

5. **Безопасность порогов**  
   `beta=0.5` жёстко штрафует FP. В продакшене это снижает нагрузку на SOC, но может пропускать low-rate DGA (медленные генераторы).  
   ✅ **Митигация:** Добавить `threshold_tuning` с `precision_recall_curve` или ensemble с правилом `chi_square > X`.
