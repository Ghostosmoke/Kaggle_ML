# 🚢 Titanic — РАЗБОР ВСЕХ БЛОКОВ (titanic-08.ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** Предсказать, выжил ли пассажир Титаника (`1`) или нет (`0`), используя только табличные данные: пол, возраст, класс билета, цену, состав семьи и имя.  
**Зачем это нужно на практике:** Это эталонный пример полного ML-пайплайна для бинарной классификации. На его примере показывается, как:
1. Превратить «грязные» сырые CSV (с пропусками, текстом, разными масштабами) в чистую числовую матрицу.
2. Избежать **утечки данных** (data leakage) из теста в трейн при обработке признаков.
3. Создать сильные признаки из косвенных данных (например, выживаемость группы по фамилии/билету, титулы из имён).
4. Автоматически подобрать настройки простой модели, чтобы получить стабильный и воспроизводимый результат для Kaggle-отправки.

**Логика всего пайплайна:** Загрузили → объединили train+test под одним флагом → почистили, создали признаки и заполнили пропуски → вернули выборки обратно → отмасштабировали числа → подобрали гиперпараметры KNN через случайный поиск → сделали прогноз → сохранили `submission.csv`.

### 🔹 БЛОК 1: Импорт библиотек + загрузка файлов
🎯 **Задача блока:** Подключить инструменты и загрузить 3 CSV-файла в память.  
📁 **Файлы/Данные:** 
- `train.csv` (891 строк, есть колонка `Survived` — правильный ответ)
- `test.csv` (418 строк, без `Survived` — нужно предсказать)
- `gender_submission.csv` (шаблон ответа: колонки `PassengerId`, `Survived`)  
Пример строки: `1,0,3,"Braund, Mr. Owen Harris",male,22,1,0,A/5 21171,7.25,,S`  
🛠 **Библиотеки:** 
- `pandas` — парсит CSV построчно, разбивает по запятым, угадывает типы (int/float/string), собирает в `DataFrame`.
- `numpy` — движок для быстрых числовых массивов. `pandas` использует его под капотом для расчётов.
- `scipy.stats.randint` — генерирует случайные целые числа из диапазона. Нужен для случайного перебора параметров модели.
- `StandardScaler` — формула: `z = (x - mean) / std`. Приводит все числа к среднему 0 и отклонению 1, чтобы возраст (0-80) не «забивал» цену билета (0-512).
- `RandomizedSearchCV` — берет словарь параметров, случайным образом выбирает 30 комбинаций, проверяет каждую через кросс-валидацию, возвращает лучшую.
- `KNeighborsClassifier` — модель KNN: строит точки в n-мерном пространстве, считает евклидово расстояние до `k` ближайших соседей, голосует за класс.  
🔄 **Что происходит с данными:** Файлы читаются в таблицы `raw_train`, `raw_test`, `submission_form`. Данные сырые: есть пропуски, текст, числа в разных масштабах.  
🔜 **Переход:** Теперь нужно склеить train и test, чтобы обработать признаки одинаково и не допустить смещения статистики.

### 🔹 БЛОК 2: Объединение train и test
🎯 **Задача блока:** Склеить обе выборки в один пул для единой обработки.  
📁 **Файлы/Данные:** Копии `raw_train` и `raw_test`.  
🛠 **Библиотеки:** `pd.concat()` — склеивает таблицы по строкам (`axis=0`), сбрасывает старые индексы (`ignore_index=True`), сохраняет порядок колонок.  
🔄 **Что происходит с данными:** В обе таблицы добавляется метка `is_train` (1 для train, 0 для test). Затем они склеиваются в `union_data`. Это нужно, чтобы статистика для обработки признаков (например, медиана возраста по титулу) считалась на всех данных сразу, без «утечки» меток `Survived` из train в test.  
🔜 **Переход:** Данные объединены, начинаем создавать новые признаки и чистить текст.

---

### 🔹 БЛОК 3: Создание признаков (Feature Engineering)
🎯 **Задача блока:** Превратить сырые строки и числа в понятные для модели цифры.  
📁 **Файлы/Данные:** Объединённая таблица `union_data`.  
🛠 **Библиотеки:** 
- `.str.extract()` — вырезает подстроки по регулярке (титулы из имён).
- `.groupby().transform()` — применяет функцию к группам, сохраняя исходный размер таблицы.
- `.map()` — заменяет значения по словарю.
- `pd.qcut()` — разбивает числа на интервалы с равным количеством объектов внутри (квантили).  
🔄 **Что происходит с данными:** 
1. Из имён вырезаются титулы (`Mr`, `Miss` и т.д.), редкие объединяются в основные. Пропуски в возрасте заполняются **медианой по титулу**.
2. Считается `Family_Size = Parch + SibSp`.
3. Вычисляется `Family_Survival`: группировка по `Фамилия + Цена билета` и `Ticket`. Если в группе другие выжили → ставим 1, если погибли → 0. Это мощный сигнал: семьи часто выживают или погибают вместе.
4. Возраст и цена делятся на квантили и кодируются числами (`AgeBin_Code`, `FareBin_Code`).
5. Пол кодируется: `male=0`, `female=1`.
6. Удаляются сырые колонки (`Name`, `Ticket`, `Cabin` и т.д.). Получаем чистую числовую таблицу.  
🔜 **Переход:** Признаки готовы, возвращаем train и test на свои места и масштабируем числа.

---

### 🔹 БЛОК 4: Разделение обратно и масштабирование
🎯 **Задача блока:** Вернуть выборки на свои места и привести признаки к единому масштабу.  
📁 **Файлы/Данные:** `union_data` с новыми признаками.  
🛠 **Библиотеки:** `StandardScaler.fit_transform()` — считает среднее и отклонение на train, применяет формулу `z = (x - μ) / σ` к train и test.  
🔄 **Что происходит с данными:** По флагу `is_train` таблица снова разрезается на `train_final` и `test_final`. Из train вынимаются `X` (признаки) и `y` (ответ `Survived`). Все признаки проходят через `StandardScaler`: теперь у них среднее ≈ 0, разброс ≈ 1. Это критично для KNN, который ищет ближайших соседей по расстоянию. Без масштабирования большие числа (цена билета) доминировали бы над маленькими (пол).  
🔜 **Переход:** Данные чистые и отмасштабированы, ищем лучшие настройки модели.

---

### 🔹 БЛОК 5: Подбор гиперпараметров (RandomizedSearchCV)
🎯 **Задача блока:** Автоматически найти идеальное количество соседей и другие настройки для KNN.  
📁 **Файлы/Данные:** Матрица признаков `model_X` и метки `model_y`.  
🛠 **Библиотеки:** 
- `RandomizedSearchCV` — вместо полного перебора выбирает `n_iter=30` случайных комбинаций из словаря, экономит время.
- `cv=10` (StratifiedKFold под капотом) — разбивает данные на 10 частей, тренирует на 9, проверяет на 1, повторяет 10 раз.  
🔄 **Что происходит с данными:** Модель пробует разное `n_neighbors` (6-22), `weights` (`uniform` или `distance`), `leaf_size`. Каждая комбинация оценивается по `roc_auc`. Лучшая комбинация запоминается: `n_neighbors=18`, `weights='uniform'`, `leaf_size=21`. Модель готова к финальному обучению.  
🔜 **Переход:** Обучаем финальную модель на всех данных и делаем предсказания для теста.

---

### 🔹 БЛОК 6: Финальный прогноз и сохранение
🎯 **Задача блока:** Обучить лучшую модель и выдать ответы для Kaggle.  
📁 **Файлы/Данные:** `model_X_test` (тестовые признаки), `submission_form` (шаблон ответа).  
🛠 **Библиотеки:** 
- `.fit()` — тренирует KNN на всей обучающей выборке с найденными параметрами.
- `.predict()` — для каждого теста считает расстояния до 18 ближайших соседей из train, берёт их метки и голосует за класс 0 или 1.
- `.to_csv()` — сохраняет в плоском текстовом формате без индексов.  
🔄 **Что происходит с данными:** Модель применяет найденные правила к тестовым данным. Получается массив из `0` и `1`. Он вставляется в шаблон `gender_submission.csv` под колонку `Survived`. Файл `submission.csv` готов к отправке на Kaggle.  
🔜 **Переход:** Работа завершена.
