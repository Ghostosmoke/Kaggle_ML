# 🚢 Titanic — РАЗБОР ВСЕХ БЛОКОВ (titanic-08.ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** Предсказать, выжил ли пассажир Титаника (`1`) или нет (`0`), используя только табличные данные: пол, возраст, класс билета, цену, состав семьи и имя.  
**Зачем это нужно на практике:** Это эталонный пример полного ML-пайплайна для бинарной классификации. На его примере показывается, как:
1. Превратить «грязные» сырые CSV (с пропусками, текстом, разными масштабами) в чистую числовую матрицу.
2. Избежать **утечки данных** (data leakage) из теста в трейн при обработке признаков.
3. Создать сильные признаки из косвенных данных (например, выживаемость группы по фамилии/билету, титулы из имён).
4. Автоматически подобрать настройки простой модели, чтобы получить стабильный и воспроизводимый результат для Kaggle-отправки.

**Логика всего пайплайна:** Загрузили → объединили train+test под одним флагом → почистили, создали признаки и заполнили пропуски → вернули выборки обратно → отмасштабировали числа → подобрали гиперпараметры KNN через случайный поиск → сделали прогноз → сохранили `submission.csv`.

### 🔹 БЛОК 1: Импорт библиотек + загрузка файлов
🎯 **Задача блока:** Подключить инструменты и загрузить 3 CSV-файла в память.  
📁 **Файлы/Данные:** 
- `train.csv` (891 строк, есть колонка `Survived` — правильный ответ)
- `test.csv` (418 строк, без `Survived` — нужно предсказать)
- `gender_submission.csv` (шаблон ответа: колонки `PassengerId`, `Survived`)  
Пример строки: `1,0,3,"Braund, Mr. Owen Harris",male,22,1,0,A/5 21171,7.25,,S`  
🛠 **Библиотеки:** 
- `pandas` — парсит CSV построчно, разбивает по запятым, угадывает типы (int/float/string), собирает в `DataFrame`.
- `numpy` — движок для быстрых числовых массивов. `pandas` использует его под капотом для расчётов.
- `scipy.stats.randint` — генерирует случайные целые числа из диапазона. Нужен для случайного перебора параметров модели.
- `StandardScaler` — формула: `z = (x - mean) / std`. Приводит все числа к среднему 0 и отклонению 1, чтобы возраст (0-80) не «забивал» цену билета (0-512).
- `RandomizedSearchCV` — берет словарь параметров, случайным образом выбирает 30 комбинаций, проверяет каждую через кросс-валидацию, возвращает лучшую.
- `KNeighborsClassifier` — модель KNN: строит точки в n-мерном пространстве, считает евклидово расстояние до `k` ближайших соседей, голосует за класс.  
🔄 **Что происходит с данными:** Файлы читаются в таблицы `raw_train`, `raw_test`, `submission_form`. Данные сырые: есть пропуски, текст, числа в разных масштабах.  
🔜 **Переход:** Теперь нужно склеить train и test, чтобы обработать признаки одинаково и не допустить смещения статистики.

### 🔹 БЛОК 2: Объединение train и test
🎯 **Задача блока:** Склеить обе выборки в один пул для единой обработки.  
📁 **Файлы/Данные:** Копии `raw_train` и `raw_test`.  
🛠 **Библиотеки:** `pd.concat()` — склеивает таблицы по строкам (`axis=0`), сбрасывает старые индексы (`ignore_index=True`), сохраняет порядок колонок.  
🔄 **Что происходит с данными:** В обе таблицы добавляется метка `is_train` (1 для train, 0 для test). Затем они склеиваются в `union_data`. Это нужно, чтобы статистика для обработки признаков (например, медиана возраста по титулу) считалась на всех данных сразу, без «утечки» меток `Survived` из train в test.  
🔜 **Переход:** Данные объединены, начинаем создавать новые признаки и чистить текст.

### 🔹 БЛОК 3: Создание признаков (Feature Engineering)
🎯 **Задача блока:** Превратить сырые строки и числа в понятные для модели цифры.  
📁 **Файлы/Данные:** Объединённая таблица `union_data`.  
🛠 **Библиотеки:** 
- `.str.extract()` — вырезает подстроки по регулярке (титулы из имён).
- `.groupby().transform()` — применяет функцию к группам, сохраняя исходный размер таблицы.
- `.map()` — заменяет значения по словарю.
- `pd.qcut()` — разбивает числа на интервалы с равным количеством объектов внутри (квантили).  
🔄 **Что происходит с данными:** 
1. Из имён вырезаются титулы (`Mr`, `Miss` и т.д.), редкие объединяются в основные. Пропуски в возрасте заполняются **медианой по титулу**.
2. Считается `Family_Size = Parch + SibSp`.
3. Вычисляется `Family_Survival`: группировка по `Фамилия + Цена билета` и `Ticket`. Если в группе другие выжили → ставим 1, если погибли → 0. Это мощный сигнал: семьи часто выживают или погибают вместе.
4. Возраст и цена делятся на квантили и кодируются числами (`AgeBin_Code`, `FareBin_Code`).
5. Пол кодируется: `male=0`, `female=1`.
6. Удаляются сырые колонки (`Name`, `Ticket`, `Cabin` и т.д.). Получаем чистую числовую таблицу.  
🔜 **Переход:** Признаки готовы, возвращаем train и test на свои места и масштабируем числа.

### 🔹 БЛОК 4: Разделение обратно и масштабирование
🎯 **Задача блока:** Вернуть выборки на свои места и привести признаки к единому масштабу.  
📁 **Файлы/Данные:** `union_data` с новыми признаками.  
🛠 **Библиотеки:** `StandardScaler.fit_transform()` — считает среднее и отклонение на train, применяет формулу `z = (x - μ) / σ` к train и test.  
🔄 **Что происходит с данными:** По флагу `is_train` таблица снова разрезается на `train_final` и `test_final`. Из train вынимаются `X` (признаки) и `y` (ответ `Survived`). Все признаки проходят через `StandardScaler`: теперь у них среднее ≈ 0, разброс ≈ 1. Это критично для KNN, который ищет ближайших соседей по расстоянию. Без масштабирования большие числа (цена билета) доминировали бы над маленькими (пол).  
🔜 **Переход:** Данные чистые и отмасштабированы, ищем лучшие настройки модели.

### 🔹 БЛОК 5: Подбор гиперпараметров (RandomizedSearchCV)
🎯 **Задача блока:** Автоматически найти идеальное количество соседей и другие настройки для KNN.  
📁 **Файлы/Данные:** Матрица признаков `model_X` и метки `model_y`.  
🛠 **Библиотеки:** 
- `RandomizedSearchCV` — вместо полного перебора выбирает `n_iter=30` случайных комбинаций из словаря, экономит время.
- `cv=10` (StratifiedKFold под капотом) — разбивает данные на 10 частей, тренирует на 9, проверяет на 1, повторяет 10 раз.  
🔄 **Что происходит с данными:** Модель пробует разное `n_neighbors` (6-22), `weights` (`uniform` или `distance`), `leaf_size`. Каждая комбинация оценивается по `roc_auc`. Лучшая комбинация запоминается: `n_neighbors=18`, `weights='uniform'`, `leaf_size=21`. Модель готова к финальному обучению.  
🔜 **Переход:** Обучаем финальную модель на всех данных и делаем предсказания для теста.

### 🔹 БЛОК 6: Финальный прогноз и сохранение
🎯 **Задача блока:** Обучить лучшую модель и выдать ответы для Kaggle.  
📁 **Файлы/Данные:** `model_X_test` (тестовые признаки), `submission_form` (шаблон ответа).

- `.to_csv()` — сохраняет в плоском текстовом формате без индексов.  
🔄 **Что происходит с данными:** Модель применяет найденные правила к тестовым данным. Получается массив из `0` и `1`. Он вставляется в шаблон `gender_submission.csv` под колонку `Survived`. Файл `submission.csv` готов к отправке на Kaggle.  
🔜 **Переход:** Работа завершена.

### 🎯 ОБЩАЯ ЦЕЛЬ & АРХИТЕКТУРА
**Задача:** Бинарная классификация выживания пассажиров (`Survived: 0/1`) по демографическим и билетным данным.  
**Ключевая особенность:** Использование **"Union Trick"** (объединение train/test перед обработкой признаков), сложная логика `Family_Survival` на основе группировок, `RandomizedSearchCV` с `roc_auc` для `KNeighborsClassifier`, строгое разделение fit/transform при масштабировании.  
**Метрика:** Kaggle Accuracy (неявно), но оптимизация ведётся по `ROC-AUC`.  
**Пайплайн:** Загрузка → Union concat → Title/Age imputation → Family survival logic → Quantile binning → StandardScaler → KNN + RandomizedSearchCV → Final predict → `submission.csv`.

---

### 🔹 РАЗБОР ПО ЭТАПАМ ВЫПОЛНЕНИЯ

#### 🔹 ЭТАП 1: Импорт & Загрузка
- Читаются `train.csv`, `test.csv`, `gender_submission.csv`. `gender_submission.csv` используется только как шаблон для сохранения результата в правильном формате столбцов.
- Импортирован `sp_randint` из `scipy.stats`, но в коде **не используется** (артефакт рефакторинга).

#### 🔹 ЭТАП 2: Union Trick (`pd.concat`)
- Создаются копии `raw_train`, `raw_test`.
- Добавляется флаг `is_train` (1/0).
- `pd.concat([train_flagged, test_flagged], ignore_index=True, sort=False)` объединяет датасеты в один пул `union_data` (~1309 строк).  
- **Зачем:** Гарантирует идентичные границы квантилей (`pd.qcut`), одинаковое маппинг титулов, согласованное заполнение пропусков. Если обрабатывать train/test раздельно, границы бинов и медианы возраста разойдутся → модель получит разное распределение признаков на inference.

#### 🔹 ЭТАП 3: Feature Engineering (`create_features`)
1. **Title Extraction:** `df['Name'].str.extract(r'([A-Za-z]+)\.')` → векторизованный regex. Редкие титулы маппятся в `Mr/Miss/Mrs`.
2. **Age Imputation:** `groupby('Title')['Age'].transform(lambda x: x.fillna(x.median()))`. Заполняет пропуски медианой по титулу (например, у `Master` медиана ~4 года, у `Mr` ~29). Сохраняет форму DataFrame.
3. **Family Size & Name:** `Parch + SibSp`, извлечение `Last_Name` через `str.split`.
4. **Family Survival Logic:** 
   - Группировка по `(Last_Name, Fare)`, затем по `Ticket`.
   - Внутри группы для каждого пассажира считается `smax = grp_df.drop(ind)['Survived'].max()`, `smin = grp_df.drop(ind)['Survived'].min()`.
   - `drop(ind)` исключает самого пассажира → **предотвращает тривиальный leakage**.
   - Если в группе кто-то выжил → `Family_Survival = 1`. Если кто-то погиб → `0`. Иначе `0.5`.
5. **Quantile Binning:** `pd.qcut(Fare, 5)`, `pd.qcut(Age, 4)` → разбивает на равные по количеству квантили, извлекает `.cat.codes`.
6. **Encoding & Drop:** `Sex` → 0/1. Удаляются сырые столбцы (`Name`, `Cabin`, `Ticket`, `Embarked` и др.).

#### 🔹 ЭТАП 4: Разделение & Масштабирование
- `union_data` разделяется обратно по флагу `is_train`.
- `model_X`, `model_y`, `model_X_test` формируются.
- `StandardScaler().fit_transform(model_X)` → вычисляет `mean`, `std` только на train. `transform(model_X_test)` применяет те же параметры. **Zero data leakage**.

#### 🔹 ЭТАП 5: `RandomizedSearchCV` для KNN
- `param_space_random`: `n_neighbors` (12 вариантов), `weights`, `leaf_size` (10 вариантов), `algorithm`.
- `n_iter=30`, `scoring='roc_auc'`, `cv=10`, `n_jobs=-1`.
- Итог: `n_neighbors=18`, `weights='uniform'`, `leaf_size=21`. `roc_auc ≈ 0.8791`.
- `cv=10` создает 300 фитов модели (30 комбинаций × 10 фолдов).

#### 🔹 ЭТАП 6: Финальный прогноз
- `best_estimator_.fit(model_X, model_y)` → переобучение на 100% train с лучшими гиперпараметрами.
- `predict(model_X_test)` → hard labels. Сохранение в `submission.csv`.

### 🧠 ВНУТРЕННЯЯ МЕХАНИКА БИБЛИОТЕК (DEEP DIVE)

| Компонент | Внутренняя механика | Почему это важно в проекте |
|:---|:---|:---|
| `pd.concat` + `ignore_index=True` | Перестраивает `RangeIndex` с 0 до `N-1`, избегая дубликатов индексов при последующих `loc`-операциях. `sort=False` сохраняет порядок колонок без лексикографической сортировки. | Без `ignore_index=True` последующие `groupby` или `loc` могли бы работать некорректно из-за неконтигуозных индексов. Union trick требует целостного индекса. |
| `str.extract(r'([A-Za-z]+)\.')` | Использует `re` через `_str_extract` в C-цикле. Возвращает `Series` с пропущенными `NaN`, если паттерн не найден. Векторизовано, работает за O(N·L), где L — длина строки. | Замена медленных `apply(lambda x: x.split()[1])`.Regex быстрее в 3–5× на текстовых колонках. |
| `groupby().transform(lambda x: x.fillna(x.median()))` | `groupby` строит hash-таблицу групп. `transform` вычисляет медиану (O(G·n log n)) и **broadcast** возвращает Series той же длины, что и исходный. `fillna` заполняет только NaN. | Лучше глобальной медианы, т.к. сохраняет возрастную структуру титулов (`Master` vs `Mr`). `transform` избегает ручного `map`/`merge`. |
| `Family_Survival` + `drop(ind)` | Итеративный `groupby` с `iterrows()`. `drop(ind)` создаёт копию подгруппы без текущего индекса. `max()/min()` работают на numpy-массиве внутри pandas. | Критичная защита от leakage. Если не дропать индекс, пассажир увидит свой же лейбл → `Family_Survival` станет точной копией `Survived` для 100% группы. |
| `pd.qcut(..., 5/4)` | Вычисляет эмпирические квантили через `numpy.percentile` (интерполяция). Присваивает интервальные метки, затем `.cat.codes` мапит в `0..K-1`. Если много дубликатов, автоматически схлопывает бины. | Обеспечивает **равномерное распределение** признаков по классам, что снижает чувствительность KNN к выбросам в `Fare`/`Age`. |
| `StandardScaler` | `(x - μ) / σ`, где `σ = sqrt(Σ(x-μ)²/N)` (population std, `ddof=0`). `fit` сохраняет `mean_`, `scale_` как `ndarray`. `transform` применяет поэлементно. | KNN основан на **евклидовом расстоянии**. Без масштабирования `Fare` (диапазон 0–512) будет доминировать над `Age` (0–80) и `Family_Size` (0–6). Scaler приводит признаки к одному масштабу. |
| `KNeighborsClassifier` | При `algorithm='auto'` выбирает между `ball_tree`, `kd_tree` и `brute` на основе эвристики: `n_samples < 30`, `n_features > 15` → `brute`, иначе дерево. `leaf_size=21` контролирует размер листового узла дерева. Расстояние по умолчанию `minkowski(p=2)` (L2). | На 1300×8 признаков `brute` часто быстрее деревьев из-за накладных расходов на построение. L2-метрика требует ортогональности и одинаковой дисперсии признаков (обеспечено `StandardScaler`). |
| `RandomizedSearchCV` | Выбирает `n_iter` случайных комбинаций из `param_distributions` (равномерно или из распределений). `cv=10` делает стратифицированные фолды. `scoring='roc_auc'` вызывает `predict_proba`, строит ROC, считает AUC через трапециевидное правило. | Ищет глобальный оптимум в пространстве гиперпараметров быстрее `GridSearchCV`. AUC оптимизирует **ранжирование** вероятностей, а не жёсткий порог, что делает модель устойчивее к сдвигу классов. |
| `KNN.predict_proba` | Не использует логистическую регрессию. Считает: `P(class=k) = (кол-во соседей класса k) / n_neighbors`. Для `weights='distance'` используется `1/distance`. | Вероятности KNN **не откалиброваны** (часто сжаты к 0.2/0.8). AUC всё ещё работает, но для пороговой оптимизации лучше `CalibratedClassifierCV` (в коде не применён). |

### ⚠️ КРИТИЧЕСКИЕ НЮАНСЫ & ТОЧКИ РОСТА

1. **`Family_Survival` и группировка по `Fare`**  
   Пассажиры с одинаковым `Last_Name` и `Fare` не всегда родственники (могут быть однофамильцы, купившие билеты по одной цене в разное время).  
   ✅ **Улучшение:** Добавить проверку `Ticket` или `Cabin` в группу, либо использовать явные `Family_ID = Last_Name + Fare + SibSp`.

2. **`iterrows()` в `create_features`**  
   Чистый Python-цикл. Для ~1300 строк это ~0.1–0.3 сек, но при росте данных до 1M+ строков станет bottleneck.  
   ✅ **Оптимизация:** Векторизовать через `groupby().agg(['max','min'])` и `merge` обратно, либо использовать `numba.njit`.

3. **KNN vs Табличные данные**  
   KNN предполагает, что евклидово расстояние имеет геометрический смысл. Бинненные признаки (`FareBin_Code`, `AgeBin_Code`) — **ординальные**, но KNN трактует их как интервальные (`2` не обязательно "вдвое дальше" от `1`, чем от `0`).  
   ✅ **Альтернатива:** One-Hot Encoding бинов, либо переход на `HistGradientBoosting`/`CatBoost` с встроенной обработкой категориальных признаков.

4. **`roc_auc` оптимизация vs `accuracy` submission**  
   `RandomizedSearchCV` максимизирует AUC, но Kaggle оценивает Accuracy (threshold=0.5). При несбалансированных вероятностях AUC↑ ≠ Accuracy↑.  
   ✅ **Фикс:** Добавить `scoring='accuracy'` или постобученный `threshold_tuning` на OOF-вероятностях.

5. **`Cabin` полностью удалён**  
   `Cabin` содержит ~77% NaN, но первые буквы (`A`, `B`, `C`, `D`, `E`, `F`, `G`, `T`) коррелируют с палубой и выживаемостью.  
   ✅ **Улучшение:** `df['Deck'] = df['Cabin'].str[0].fillna('U')`, затем Target Encoding или частотное кодирование.

6. **`scipy.stats.randint` импортирован, но не использован**  
   `leaf_options = list(range(1, 50, 5))` → фиксированный список.  
   ✅ **Чистка:** Удалить импорт или заменить на `param_distributions={'leaf_size': sp_randint(1, 50)}` для истинного случайного поиска.
