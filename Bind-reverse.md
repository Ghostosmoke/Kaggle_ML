# 🛡️ Bind/Reverse Shell Detection — РАЗБОР ВСЕХ БЛОКОВ (bind-reverse (1).ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** По тексту bash-команд (`shell`) определить, является ли попытка создания обратного (reverse) или привязанного (bind) шелла вредоносной (`1`) или легитимной (`0`).  
**Зачем это нужно на практике:** В серверных логах и аудиторских системах накапливаются тысячи команд. Вручную их разбирать долго. Решение автоматически сканирует команды, ищет паттерны сетевых подключений, обфускации, подозрительные порты/утилиты и помечает сессии для SOC-аналитиков.  
**Ключевая логика пайплайна:** 
1. Загрузили `.parquet` файлы (train/test), нашли колонку с метками.
2. Извлекли ручные признаки (IP, порты, флаги, утилиты, regex-паттерны атак).
3. Векторизовали текст двумя TF-IDF (по словам и по символам), чтобы поймать и команды, и обфускацию.
4. Склеили всё в одну разреженную матрицу (~20k признаков) через `scipy.sparse`.
5. Обучили ансамбль из 4 моделей через 5-фолдовую CV, усреднили вероятности.
6. Оптимизировали порог срабатывания под метрику F1, сгенерировали `submission.csv`.

🎯 **Задача блока:** Подключить инструменты, зафиксировать случайность и подготовить окружение.  
📁 **Файлы/Данные:** Пока не загружаются. Готовятся пространства импортов.  
🛠 **Библиотеки:** 
- `pandas` / `numpy` — таблицы и матрицы.
- `re`, `string` — поиск паттернов и работа со спецсимволами.
- `scipy.sparse` — хранение разреженных матриц (экономит ГБ памяти).
- `sklearn` — TF-IDF, логистическая регрессия, RF, SVC, NaiveBayes, кросс-валидация, метрики.
- `pickle` — сериализация (сохранение моделей и векторизаторов на диск).
🔄 **Что происходит с данными:** Устанавливается `np.random.seed(42)`, отключаются предупреждения `warnings.filterwarnings('ignore')`. Все переменные инициализированы, среда готова к работе с текстом и моделями.  
🔜 **Переход:** Загружаем сырые `.parquet` файлы.

### 🔹 БЛОК 2: Поиск и загрузка данных
🎯 **Задача блока:** Автоматически найти train/test файлы среди всех доступных, проверить наличие меток и загрузить их.  
📁 **Файлы/Данные:** `train.parquet` (10 950 строк, колонки `shell`, `label`), `test.parquet` (8 654 строки, `ID`, `shell`). Формат Parquet — колоночный, сжатый, читается быстрее CSV.  
🛠 **Библиотеки:** `glob`, `os`, `pd.read_parquet` — рекурсивный поиск файлов и быстрый парсинг бинарного формата.  
🔄 **Что происходит с данными:** Скрипт сканирует `/kaggle/input/`, находит parquet-файлы, проверяет наличие колонок `label`/`target`. Находит `train.parquet`, нормализует имена колонок, удаляет строки с пропусками. Распределение классов: 9320 `0` (чистые), 202 `1` (вредоносные) → сильный дисбаланс ~46:1.  
🔜 **Переход:** Данные загружены, пишем функцию извлечения признаков из текста команд.

---

### 🔹 БЛОК 3: Инженерные признаки (Shell Commands)
🎯 **Задача блока:** Превратить строку bash-команды в набор числовых индикаторов атаки.  
📁 **Файлы/Данные:** Колонка `shell` (текст команд, например: `nc -lvp 4444 -e /bin/bash`).  
🛠 **Библиотеки:** `re` (регулярки), `collections.Counter` (подсчет символов для статистики).  
🔄 **Что происходит с данными:** Функция `extract_advanced_features()` для каждой команды считает:
1. **Базовая статистика:** длина, кол-во слов, доля спецсимволов и цифр.
2. **Паттерны атак:** reverse/bind shell, загрузка скриптов (`curl|bash`), обфускация (`base64`, `\x`), `eval/exec`.
3. **Сеть:** наличие IP (частные/внешние), порты (особенно `4444`, `5555`, `1337`).
4. **Утилиты и флаги:** `nc`, `bash`, `python`, флаги `-e`, `-c`, `-i`, `-l`.
Результат — словарь признаков → `DataFrame`.  
🔜 **Переход:** Ручные признаки готовы, векторизуем сам текст команд.

---

### 🔹 БЛОК 4: TF-IDF Векторизация (Word + Char)
🎯 **Задача блока:** Превратить текст команд в числа, захватив и целые слова, и последовательности символов.  
📁 **Файлы/Данные:** Текст из колонки `shell`.  
🛠 **Библиотеки:** `TfidfVectorizer` (два экземпляра).  
🔄 **Что происходит с данными:** 
- **Word TF-IDF:** `analyzer='word'`, `ngram_range=(1,4)`, `max_features=15000`. Ловит команды, флаги, сочетания слов.
- **Char TF-IDF:** `analyzer='char_wb'`, `ngram_range=(4,8)`, `max_features=15000`. Ловит подстроки (полезно для обфускации и коротких команд).
Оба обучаются на train, преобразуют текст в разреженные матрицы. Сохраняются в `vectorizers.pkl`.  
🔜 **Переход:** Вектора и ручные признаки готовы, склеиваем их в одну матрицу.

---

### 🔹 БЛОК 5: Сборка финальной матрицы признаков
🎯 **Задача блока:** Объединить TF-IDF признаки и инженерные признаки в одну матрицу без переполнения памяти.  
📁 **Файлы/Данные:** Матрицы Word/Char TF-IDF и DataFrame инженерных признаков.  
🛠 **Библиотеки:** `scipy.sparse.hstack`, `csr_matrix` — горизонтальное склеивание разреженных матриц и конвертация numpy-массива в sparse формат.  
🔄 **Что происходит с данными:** 
1. Применяем векторизаторы к train/test → получаем две матрицы.
2. Вызываем `extract_advanced_features()`, конвертируем результат в `np.float32` (критично для scipy).
3. `hstack([X_word, X_char, X_eng])` → склеивает в одну матрицу без копирования данных.
Итог: Train `(9522, 20043)`, Test `(8654, 20043)`. Тип данных `float32` экономит память вдвое.  
🔜 **Переход:** Матрица готова, запускаем обучение ансамбля.

---

### 🔹 БЛОК 6: Обучение моделей + Кросс-валидация
🎯 **Задача блока:** Честно оценить 4 модели на CV, обучить финальные версии и сохранить их.  
📁 **Файлы/Данные:** `X_train` (20k колонок), `y_train` (0/1).  
🛠 **Библиотеки:** `StratifiedKFold`, `LogisticRegression`, `RandomForestClassifier`, `LinearSVC`, `MultinomialNB`, `pickle`.  
🔄 **Что происходит с данными:** 
1. Данные делятся на 5 фолдов с сохранением пропорции классов.
2. Каждая модель обучается 5 раз, предсказывает OOF (Out-Of-Fold), считается F1. (LR ~0.98, RF ~1.0, SVC ~0.99, NB ~0.94).
3. Модели переобучаются на 100% train данных.
4. Все модели + векторизаторы сохраняются в `final_models.pkl` для быстрого использования.  
🔜 **Переход:** Модели обучены, ищем оптимальный порог отсечки.

---

### 🔹 БЛОК 7: Оптимизация порога (Threshold)
🎯 **Задача блока:** Найти значение вероятности, при котором F1-метрика максимальна (вместо стандартных 0.5).  
📁 **Файлы/Данные:** OOF вероятности от лучшей модели, `y_train`.  
🛠 **Библиотеки:** `cross_val_predict`, `f1_score`, `np.arange`.  
🔄 **Что происходит с данными:** 
1. Генерируем OOF вероятности через 5-фолдовую CV.
2. Перебираем пороги от 0.1 до 0.9 с шагом 0.01.
3. Для каждого порога: `pred = (proba >= thresh).astype(int)`, считаем F1.
4. Находим оптимум (в логе ~0.62), сохраняем в `optimal_threshold.txt`. Визуализируем график F1 vs Threshold.  
🔜 **Переход:** Порог зафиксирован, генерируем финальный submission.

---

### 🔹 БЛОК 8: Финальный прогноз и сохранение
🎯 **Задача блока:** Применить ансамбль к тесту, усреднить предсказания, применить порог, сохранить ответ.  
📁 **Файлы/Данные:** `X_test`, `df_test['ID']`, сохраненные модели и порог.  
🛠 **Библиотеки:** `pickle.load`, `predict_proba`, `np.mean`, `pd.DataFrame.to_csv`.  
🔄 **Что происходит с данными:** 
1. Загружаем модели и порог из файлов.
2. Каждая модель предсказывает вероятности на `X_test`.
3. Вероятности усредняются (`np.mean` по моделям) → получается ансамблевая вероятность.
4. Среднее сравнивается с порогом → получается 0 или 1.
5. Формируется DataFrame с `ID` и `label`, сохраняется в `submission.csv`.  
🔜 **Переход:** Работа завершена.
