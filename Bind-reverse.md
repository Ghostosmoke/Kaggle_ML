# 🛡️ Bind/Reverse Shell Detection — РАЗБОР ВСЕХ БЛОКОВ (bind-reverse (1).ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** По тексту bash-команд (`shell`) определить, является ли попытка создания обратного (reverse) или привязанного (bind) шелла вредоносной (`1`) или легитимной (`0`).  
**Зачем это нужно на практике:** В серверных логах и аудиторских системах накапливаются тысячи команд. Вручную их разбирать долго. Решение автоматически сканирует команды, ищет паттерны сетевых подключений, обфускации, подозрительные порты/утилиты и помечает сессии для SOC-аналитиков.  
**Ключевая логика пайплайна:** 
1. Загрузили `.parquet` файлы (train/test), нашли колонку с метками.
2. Извлекли ручные признаки (IP, порты, флаги, утилиты, regex-паттерны атак).
3. Векторизовали текст двумя TF-IDF (по словам и по символам), чтобы поймать и команды, и обфускацию.
4. Склеили всё в одну разреженную матрицу (~20k признаков) через `scipy.sparse`.
5. Обучили ансамбль из 4 моделей через 5-фолдовую CV, усреднили вероятности.
6. Оптимизировали порог срабатывания под метрику F1, сгенерировали `submission.csv`.

3. **Сеть:** наличие IP (частные/внешние), порты (особенно `4444`, `5555`, `1337`).

### 🔹 2. `re` (Regular Expressions) — Парсинг команд
- **Механика:** При первом вызове `re.search()` шаблон компилируется в конечный автомат (DFA/NFA) через `_sre_compile`. CPython кэширует последние **512 скомпилированных паттернов** в LRU-кэше. Повторные вызовы тех же строк не перекомпилируют шаблон.
- **Нюанс в коде:** В `extract_advanced_features()` используется `re.search()` для бинарных флагов (останавливается на первом совпадении → O(N)) и `re.findall()` для IP/портов (собирает все вхождения → O(N)). Это оптимально: не нужно искать все IP, если достаточно знать `ip_count > 0`.
- **⚠️ Потенциальная оптимизация:** Вынести `re.compile()` за цикл `for cmd in shell_commands`. В текущем виде компиляция происходит внутри цикла, но кэш спасает производительность. На 10k+ строках это экономит ~15–20% времени.

### 🔹 3. `TfidfVectorizer` — Два экземпляра (Word + Char)
| Параметр | Внутренняя механика | Зачем в этом проекте |
|:---|:---|:---|
| `analyzer='word'` / `'char_wb'` | `char_wb` добавляет пробелы по границам слов перед нарезкой n-грамм. `nc -e` → `␣nc␣`, `␣-e␣`. Это предотвращает "склеивание" команд с аргументами (`nce` вместо `nc` + `-e`). | Ловит обфускацию и короткие утилиты, которые Word-TFIDF может пропустить из-за `min_df=2`. |
| `ngram_range=(1,4)` / `(4,8)` | Создает словарь из униграмм..4-грамм и 4..8-символьных подстрок. Количество фич растет экспоненциально, но `max_features=15000` отсекает хвост по TF-IDF весу. | (1,4) ловит связки вроде `bash -c`, `nc -lvp`. (4,8) ловит base64-куски, hex-последовательности, хеши, которые не делятся на слова. |
| `min_df=2` | Игнорирует токены, встречающиеся в <2 документах. Отсекает опечатки и уникальные артефакты логов. | Защищает от переобучения на шуме. |
| `max_df=0.90` | Игнорирует токены, встречающиеся в >90% документов. | Убирает мусор вроде `-`, `/`, `bash` (если они есть почти во всех чистых логах), который не несет discriminative power. |
| `sublinear_tf=True` | Применяет формулу `tf' = 1 + log(tf)`. | Сглаживает взрывной рост веса для команд, повторяющихся в одной строке (например, `; ls ; ls ; ls`). Без этого TF-IDF перегрузит модель частотными артефактами. |
| `dtype=np.float32` | Хранит матрицу в 4-байтном формате. | Экономит ~750 МБ RAM на `(9522, 20043)`. Для sklearn точности `float32` хватает. |

### 🔹 4. `scipy.sparse` — `csr_matrix` & `hstack`
- **CSR (Compressed Sparse Row):** Хранит 3 массива: `data` (ненулевые значения), `indices` (номера столбцов), `indptr` (указатели на начало каждой строки). Доступ к строке: O(1), к столбцу: O(nnz). Идеален для построчного обучения (`model.fit(X, y)`).
- **`hstack([X_word, X_char, X_eng])`:** Не создает плотную копию. Просто пересчитывает `indptr` и конкатенирует `data`/`indices` массивы. Сложность: O(nnz₁ + nnz₂ + nnz₃).
- **Критичный фикс в Cell 5:** `X_train_eng = X_train_eng.astype(np.float32)` перед `csr_matrix()`. Если оставить `float64` или `int`, `scipy` попытается привести к общему типу, создав временную плотную матрицу → **Out-Of-Memory**.

### 🔹 5. Модели: Математика и Параметры

#### 📘 `LogisticRegression(C=0.5, class_weight='balanced', max_iter=2000, solver='lbfgs')`
- **`solver='lbfgs'`**: Limited-memory BFGS. Аппроксимирует обратную матрицу Гессе, храня только последние `m=10` шагов. Сходится за 10–50 итераций на средних датасетах. Не требует стохастичности, устойчив к шуму.
- **`C=0.5`**: Обратная сила регуляризации. `Loss = LogLoss + (1/C) * ||w||²`. `C=0.5` → `α=2.0`. Сильнее штрафует большие веса, предотвращая реакцию на редкие токены обфускации.
- **`class_weight='balanced'`**: Автоматически вычисляет `w_j = n_samples / (n_classes * n_samples_j)`. При дисбалансе 46:1 вес класса `1` ≈ 23, класса `0` ≈ 0.5. Это эквивалентно умножению градиента ошибки на миноритарном классе в 46 раз.

#### 🌳 `RandomForestClassifier(n_estimators=200, max_depth=15, class_weight='balanced', n_jobs=-1)`
- **Bagging + Random Subspace**: Каждое дерево видит ~63.2% строк (bootstrap). `max_features='sqrt'` → случайно выбирает ~140 признаков из 20k для каждого разбиения. Это декоррелирует деревья.
- **`max_depth=15`**: Без ограничения RF на тексте мгновенно переобучается (запоминает уникальные комбинации команд). Глубина 15 дает ~2¹⁵ ≈ 32k листьев, что достаточно для нелинейных правил (`nc` + `-e` + порт `>4000`), но не позволяет запомнить шум.
- **`n_jobs=-1`**: Использует `joblib` (process-based, не thread-based из-за GIL). Копирует данные в дочерние процессы через `fork`. На 8 ядрах ускоряет обучение в 6–7×.

#### ⚡ `LinearSVC(C=0.5, class_weight='balanced', max_iter=3000, dual='auto')`
- **Механика**: Минимизирует Hinge Loss: `L = ½||w||² + C * Σmax(0, 1 - y_i(w·x_i + b))`. Использует `liblinear` (координатный спуск).
- **`dual='auto'`**: В sklearn 1.2+ автоматически выбирает форму задачи. У нас `n_samples=9522 < n_features=20043` → переключается в `dual=False` (прямая задача). Это критично: двойная форма имеет сложность O(n_samples²), прямая O(n_samples·n_features). При 20k признаков двойная форма убила бы память.
- **⚠️ Нюанс**: `LinearSVC` **не имеет** `predict_proba`. Если Cell 7 попытается вызвать `cross_val_predict(..., method='predict_proba')` на SVC, код упадет. В ноутбуке это обходится fallback-логикой (загружается LR/RF), но в продакшене SVC нужно оборачивать в `CalibratedClassifierCV`.

#### 📊 `MultinomialNB(alpha=0.1)`
- **Механика**: Байесовский классификатор для дискретных признаков. `P(c|x) ∝ P(c) * Π P(x_i|c)`. Работает за один проход O(N·D).
- **`alpha=0.1` (Lidstone smoothing)**: Добавляет псевдо-счет 0.1 к каждому токену. Предотвращает `0 * anything = 0`. Без этого встреча неизвестной команды в тесте обнулит вероятность всего класса. `0.1 < 1.0` означает более агрессивное доверие к обученным частотам, меньше "сглаживания".

### 🔹 6. `StratifiedKFold` & `cross_val_predict`
- **`StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`**: Делит данные на 5 фолдов, сохраняя пропорцию `9320:202` в каждом. `shuffle=True` критичен, так как логи часто отсортированы по времени/типу.
- **`cross_val_predict(..., method='predict_proba')`**: Обучает модель на 4 фолдах, предсказывает на 5-м. "Склеивает" предсказания в порядке исходного индекса. Гарантирует **OOF (Out-Of-Fold)** вероятности: каждый объект предсказан моделью, которая его не видела. Это "чистые" данные для оптимизации порога без data leakage.

---

### 🔹 7. Оптимизация порога (Threshold Tuning)
- **Цикл `np.arange(0.1, 0.9, 0.01)`**: Для каждого порога считает `pred = (proba >= thresh).astype(int)` и `f1_score`.
- **Математика F1**: `F1 = 2 * (P * R) / (P + R)`. Смещение порога ↓ повышает Recall, но снижает Precision. Смещение ↑ повышает Precision, но снижает Recall.
- **Почему оптимум ~0.62?** При дисбалансе 46:1 стандартный `0.5` дает слишком много FP (чистые команды с редкими токенами помечаются как вредоносные). Повышение до `0.62` отсекает "шумные" вероятности, оставляя только уверенные предсказания, что максимизирует F1.
- **График в Cell 7**: Если кривая F1 плоская → модель плохо откалибрована (вероятности сжаты к 0.5). В вашем случае кривая имеет четкий пик → вероятности хорошо разделены.

### 🔹 8. Ансамбль и Сериализация
- **Ручное Soft Voting**: `np.mean(all_preds, axis=0)` + `np.round()`. Усреднение вероятностей снижает дисперсию (Variance Reduction). Ошибки LR (линейные) и RF (нелинейные) часто некоррелированы, поэтому их среднее стабильнее. `VotingClassifier` из импортов не используется, вероятно, автор оставил его как резерв или отказался из-за жесткой архитектуры.
- **`pickle`**: Сериализует граф объектов Python. Для sklearn сохраняет `coef_`, `intercept_`, структуру деревьев, словари токенизаторов. 
- **⚠️ Нюанс**: `pickle` привязан к версии Python и sklearn. Перенос модели требует идентичных сред. Альтернатива для продакшена: `joblib` (оптимизирован для numpy-массивов внутри моделей) или экспорт в `ONNX`.
