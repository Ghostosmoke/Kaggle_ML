# 📘 1. `titanic-08.ipynb` — Классификация выживших на Титанике

## 📁 Входные файлы
| Файл | Что внутри | Зачем нужен |
|------|-----------|-------------|
| `train.csv` | Данные пассажиров: пол, возраст, класс каюты, цена билета, выжил/нет | Обучение модели |
| `test.csv` | Те же данные, но без колонки "выжил" | Предсказание для отправки на конкурс |
| `gender_submission.csv` | Шаблон ответа: `PassengerId`, `Survived` | Чтобы сохранить результат в правильном формате |

## 🔄 Как данные превращаются в числа
```
Сырые данные → Очистка → Новые признаки → Масштабирование → Модель
```

1. **Объединяем train и test** → чтобы одинаково обработать признаки
2. **Извлекаем титулы** из имени (`Mr`, `Mrs`, `Miss`) → группировка по социальному статусу
3. **Заполняем пропуски** в возрасте медианой по титулу → чтобы не терять данные
4. **Считаем размер семьи** = родители + дети + супруги → новый признак
5. **Family_Survival** → если родственники выжили, ставим 1, если погибли — 0
6. **Биннинг** → делим возраст и цену на 4-5 групп (квантили) → убираем выбросы
7. **Кодируем пол** → `male=0`, `female=1` → модель понимает только числа
8. **StandardScaler** → приводим все признаки к одному масштабу (среднее=0, разброс=1)

## 📚 Простые объяснения терминов

| Термин | Простыми словами |
|--------|-----------------|
| **Feature Engineering** | Придумывание новых признаков из старых данных. Как из имени вытащить титул, из цены билета — группу богатства |
| **StandardScaler** | "Выравниватель" данных. Если один признак в диапазоне 0-1, а другой 0-1000, второй задавит первый. Скалер делает их сравнимыми |
| **qcut (квантильный биннинг)** | Делит числа на группы так, чтобы в каждой было примерно одинаковое количество людей. Не по равным отрезкам, а по количеству |
| **KNN (K-Nearest Neighbors)** | Алгоритм "скажи мне, кто твои соседи". Для нового пассажира ищет похожих в тренировке и смотрит, выжили они или нет |
| **RandomizedSearchCV** | Умный перебор настроек модели. Пробует 30 случайных комбинаций параметров, выбирает лучшую по кросс-валидации |
| **ROC-AUC** | Метрика качества: насколько хорошо модель отличает выживших от погибших. 1.0 = идеально, 0.5 = как подбросить монетку |
| **Cross-validation (кросс-валидация)** | Честная проверка: разбиваем данные на 10 частей, 9 тренируем, 1 проверяем. Повторяем 10 раз, усредняем результат |

# 📘 2. `wtf-whos-talking-first.ipynb` — Классификация приложений по сетевым пакетам

## 📁 Входные файлы
| Файл | Что внутри | Зачем нужен |
|------|-----------|-------------|
| `train.csv` | 30 колонок с длинами пакетов (`tcp_len1`...`tcp_len30`) + метка приложения | Обучение нейросети |
| `test.csv` | Те же 30 колонок, но без метки | Предсказание типа приложения |

## 🔄 Как данные превращаются в тензор
```
CSV → Числовая матрица → Нормализация → Размер + Направление → 3D-тензор → CNN
```

1. **Читаем CSV с `int16`** → экономим память (в 2 раза меньше чем `int64`)
2. **Нормализуем** → делим на 1500 (максимальный размер пакета, MTU) → все значения от 0 до 1
3. **Разделяем на size и direction**:
   - `size = abs(значение)` → насколько большой пакет
   - `direction = sign(значение)` → входящий (-1), исходящий (1), нулевой (0)
4. **Стекируем** → получаем тензор формы `(число_примеров, 30, 2)`:
   - 30 = последовательность пакетов
   - 2 = два канала: размер и направление

## 📚 Простые объяснения терминов

| Термин | Простыми словами |
|--------|-----------------|
| **Tensor (тензор)** | Многомерный массив чисел. Как таблица, но может быть 3D, 4D и больше. Нейросети "видят" данные как тензоры |
| **float16** | Число с плавающей точкой, занимающее 2 байта вместо 4. Меньше точность, но в 2 раза быстрее и экономнее памяти |
| **Conv1D (одномерная свёртка)** | "Скользящее окно" по последовательности. Фильтр проходит по пакетам, ищет локальные паттерны (например, 3 пакета подряд = рукопожатие) |
| **BatchNormalization** | "Стабилизатор" обучения. Нормализует выходы каждого слоя, чтобы градиенты не взрывались и обучение шло быстрее |
| **GlobalAveragePooling** | Усреднение всей последовательности в один вектор. Вместо того чтобы "расплющивать" данные (что создаёт миллионы параметров), просто берём среднее |
| **Dropout** | "Случайное выключение" нейронов во время обучения. Заставляет сеть учить устойчивые признаки, а не запоминать шум |
| **EarlyStopping** | "Стоп-кран" для обучения. Если модель перестала улучшаться на валидации 2 эпохи подряд — останавливаем, чтобы не переобучиться |
| **ReduceLROnPlateau** | "Замедление" обучения. Если модель застряла, уменьшаем шаг обучения (learning rate), чтобы она могла аккуратнее подойти к минимуму ошибки |
| **StratifiedKFold** | Честное разбиение на фолды с сохранением пропорций классов. Важно, когда одного класса мало (дисбаланс) |

# 📘 3. `dga-v2 (1).ipynb` — Обнаружение сгенерированных доменов (DGA)

## 📁 Входные файлы
| Файл | Что внутри | Зачем нужен |
|------|-----------|-------------|
| `train.csv` | Колонки: `domain` (домен), `label` (0=легитимный, 1=DGA) | Обучение модели |
| `test.csv` | Колонка `domain` без метки | Предсказание для отправки |
| `web.txt` (опционально) | Список популярных доменов (alexa, tranco) | Проверка, встречается ли домен в "белом списке" |

## 🔄 Как домен превращается в 28 признаков
```
Домен → Очистка → Статистики + Паттерны → Вектор из 28 чисел → CatBoost
```

1. **Очистка домена**: убираем `http://`, `https://`, `www.`, путь после `/`
2. **Разделяем имя и TLD**: `example.com` → `example` + `com`
3. **Считаем базовые статистики**: длина, доля цифр, доля букв, энтропия
4. **Энтропия Шеннона** → мера "случайности". Высокая = похоже на сгенерированный
5. **Chi-Square** → сравниваем распределение букв с английским языком. Сильное отклонение = подозрительно
6. **Редкие биграммы/триграммы** → считаем, сколько пар/троек букв встречаются только 1 раз. У DGA их много
7. **Последовательности согласных/гласных** → `max 4 согласных подряд` = редкость в обычных словах
8. **Проверка популярности** → есть ли домен в списке известных сайтов

## 📚 Простые объяснения терминов

| Термин | Простыми словами |
|--------|-----------------|
| **DGA (Domain Generation Algorithm)** | Алгоритм, которым вирусы генерируют сотни случайных доменов для связи с хакером. Наша задача — найти их |
| **Энтропия Шеннона** | Мера неопределённости. Если буквы распределены равномерно — энтропия высокая (случайно). Если есть частые буквы — низкая (осмысленно) |
| **Chi-Square (хи-квадрат)** | Статистический тест: "насколько наблюдаемое распределение отличается от ожидаемого". Большое значение = домен не похож на английский текст |
| **Bigram/Trigram** | Пара/тройка букв подряд. В словах есть частые сочетания (`th`, `ing`), в случайных строках — нет |
| **CatBoost** | Градиентный бустинг от Яндекса. Строит деревья последовательно, каждое новое исправляет ошибки предыдущего. Отлично работает на табличных данных |
| **scale_pos_weight** | "Усилитель" для редкого класса. Если классов 60/40, модель может игнорировать меньший. Этот параметр штрафует ошибки на нём сильнее |
| **AUC (Area Under Curve)** | Метрика: насколько хорошо модель ранжирует примеры (DGA выше, чем легитимные). Не зависит от порога классификации |
| **F-beta score** | Метрика, где можно настроить баланс между точностью и полнотой. При beta=0.5 важнее не ошибаться (меньше ложных срабатываний) |

# 📘 4. `http-malware (4).ipynb` — Обнаружение вредоносного HTTP-трафика

## 📁 Входные файлы
```
train/
├── clean/
│   ├── file_001.jsonl
│   ├── file_002.jsonl
│   └── ...
└── malware/
    ├── file_101.jsonl
    ├── file_102.jsonl
    └── ...
```

| Файл | Что внутри | Зачем нужен |
|------|-----------|-------------|
| `*.jsonl` в `clean/` | JSON-строки: массив, где `[2]` содержит объект с `rqs` (запрос) и `rsp` (ответ) | Примеры чистого трафика |
| `*.jsonl` в `malware/` | То же, но с вредоносными запросами | Примеры атак |

## 🔄 Как лог превращается в текст для TF-IDF
```
JSONL → Парсинг → Извлечение rqs/rsp → Текст "ключ:значение" → Векторизация → Модель
```

1. **Читаем JSONL построчно** → каждая строка = одна транзакция
2. **Берём 3-й элемент массива** (`obj[2]`) → там лежит объект транзакции
3. **Извлекаем `rqs` и `rsp`** → словари с заголовками запроса и ответа
4. **Превращаем в текст**: `User-Agent:Bot  Host:evil.com  Method:POST`
5. **Фильтруем короткие** → если текст < 20 символов, пропускаем (мало информации)
6. **TF-IDF векторизация** → превращаем текст в разреженную матрицу (строки = транзакции, столбцы = слова/фразы)

## 📚 Простые объяснения терминов

| Термин | Простыми словами |
|--------|-----------------|
| **JSONL** | Формат, где каждая строка — отдельный JSON-объект. Удобно для больших файлов: можно читать построчно, не загружая всё в память |
| **TF-IDF** | Способ превратить текст в числа. Часто встречающиеся слова получают маленький вес, редкие но важные — большой. Как "важность слова в документе относительно всей коллекции" |
| **ngram_range=(1,4)** | Учитываем не только отдельные слова, но и фразы из 2, 3, 4 слов. `User-Agent:Bot` важнее, чем просто `Bot` |
| **sublinear_tf=True** | Применяем логарифм к частоте слова. Чтобы очень частые слова не доминировали: `log(1+частота)` вместо просто `частота` |
| **sparse matrix (разреженная матрица)** | Матрица, где большинство значений = 0. Хранится эффективно: только ненулевые элементы. Идеально для TF-IDF, где каждое слово есть в малой части документов |
| **Logistic Regression** | Простая линейная модель для классификации. Рисует прямую (или гиперплоскость), разделяющую классы. Быстрая и хорошо работает на текстовых данных |
| **LightGBM** | Быстрый градиентный бустинг. Строит деревья "вглубь" (leaf-wise), использует гистограммы для ускорения. Отлично ловит нелинейные зависимости |
| **precision_recall_curve** | График, показывающий баланс между точностью (сколько из предсказанных "malware" действительно вредоносны) и полнотой (сколько реальных "malware" мы нашли) |
| **Optimal threshold** | Порог вероятности, при котором модель выдаёт максимальный F1. Не всегда 0.5! Если классов мало, порог может быть 0.3 или 0.7 |

# 📘 5. `bind-reverse (1).ipynb` — Обнаружение shell-команд (bind/reverse shell)

## 📁 Входные файлы
| Файл | Что внутри | Зачем нужен |
|------|-----------|-------------|
| `train.parquet` | Колонки: `shell` (текст команды), `label` (0=чистая, 1=атака) | Обучение модели |
| `test.parquet` | Колонки: `ID`, `shell` (без метки) | Предсказание для отправки |

## 🔄 Как команда превращается в признаки
```
Shell-команда → Текст + Regex-паттерны → 2 типа TF-IDF + 40 engineered features → Объединение → Ансамбль моделей
```

1. **TF-IDF word (1-4 граммы)** → ловит слова и фразы: `bash`, `-c`, `/dev/tcp`
2. **TF-IDF char_wb (4-8 граммы)** → ловит символьные паттерны: обфускация, опечатки, кодировки
3. **Regex-инжиниринг** → ищем паттерны атак:
   - `reverse_shell`: `/dev/tcp/`, `bash -i`, `0>&1`
   - `bind_shell`: `nc -l`, `ncat -l`
   - `obfuscation`: `base64`, `\x41`, `eval(`
4. **Сетевые индикаторы** → IP-адреса, порты (4444, 1337), домены
5. **Опасные утилиты** → `nc`, `curl`, `wget`, `python -c`
6. **Статистики** → длина, доля спецсимволов, энтропия, количество пайпов `|`, редиректов `>`
7. **hstack** → объединяем все признаки в одну большую разреженную матрицу

## 📚 Простые объяснения терминов

| Термин | Простыми словами |
|--------|-----------------|
| **Parquet** | Формат хранения табличных данных. Сжатый, быстрый для чтения, сохраняет типы данных. Как "умный CSV" |
| **Regex (регулярные выражения)** | Шаблоны для поиска текста. `r'nc\s+-l'` найдёт `nc -l`, `nc  -l`, `nc	-l` (с любым пробелом) |
| **char_wb analyzer** | TF-IDF, который разбивает текст на символы, но учитывает границы слов. Ловит обфускацию: `b a s h` или `bash` с вставками |
| **hstack (horizontal stack)** | "Склейка" матриц по столбцам. Как приклеить новые колонки к таблице, не копируя данные целиком |
| **Ensemble (ансамбль)** | Команда моделей. Каждая ловит свои паттерны, вместе — точнее. Как совет экспертов: один может ошибиться, большинство — реже |
| **Hard voting** | Каждая модель голосует "0" или "1", побеждает большинство. Проще и стабильнее, когда пороги уже подобраны |
| **CalibratedClassifierCV** | "Калибровщик" вероятностей. Делает так, чтобы предсказанная вероятность 0.8 действительно означала 80% шанс правильного ответа |
| **StratifiedKFold** | Разбиение данных на части с сохранением пропорции классов. Чтобы в каждом фолде было примерно 9320 чистых и 202 атаки |

# 🔑 Общие принципы для всех проектов

## 📥 Что общего во входных данных
```
Текст / Таблица / Последовательность → Очистка → Числа → Модель → Предсказание
```

| Тип данных | Пример | Как превращаем в числа |
|-----------|--------|----------------------|
| Текст | `bash -i >& /dev/tcp/...` | TF-IDF, regex-фичи, n-граммы |
| Таблица | Возраст, пол, цена билета | Стандартизация, биннинг, кодирование |
| Последовательность | 30 длин пакетов | Нормализация, разделение на size/direction, тензор |

## 🧠 Простые аналогии для сложных концепций

| Концепция | Аналогия |
|-----------|----------|
| **Машинное обучение** | Ученик решает задачи, учитель говорит "правильно/неправильно". Со временем ученик учится решать сам |
| **Признаки (features)** | Характеристики объекта. Для человека: рост, вес, цвет глаз. Для домена: длина, энтропия, редкие буквы |
| **Переобучение** | Ученик вызубрил ответы на конкретные задачи, но не понял тему. На новом тесте провалится |
| **Кросс-валидация** | Не один большой экзамен, а 5 маленьких. Усредняем оценки — честнее |
| **Ансамбль** | Совет из 5 экспертов. Один может ошибиться, но если 4 говорят одно — скорее всего, это правда |
| **Порог классификации** | "Планка" для решения. Если вероятность > 0.6 — считаем "malware". Можно поднять или опустить планку в зависимости от задачи |
| **Дисбаланс классов** | Если 95% примеров — "чистые", модель может просто всегда говорить "чистый" и быть права в 95% случаев, но пропускать все атаки |

## 🛠️ Инструменты, которые встречаются везде

| Инструмент | Зачем | Простыми словами |
|-----------|-------|-----------------|
| `pandas` | Работа с таблицами | "Excel на стероидах" для Python |
| `numpy` | Матричные вычисления | Быстрые операции с числами, как калькулятор для массивов |
| `scikit-learn` | Классические ML-алгоритмы | Готовые модели: KNN, логистическая регрессия, случайный лес |
| `tqdm` | Прогресс-бар в циклах | Показывает, сколько осталось ждать, когда обрабатываешь много данных |
| `gc.collect()` | Очистка памяти | "Мусорщик": удаляет ненужные данные, чтобы не переполнить память |
| `random_state=42` | Фиксация случайности | Чтобы результаты можно было повторить: один и тот же "случайный" выбор каждый раз |
