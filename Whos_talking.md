# 📡 Who's Talking — РАЗБОР ВСЕХ БЛОКОВ (wtf-whos-talking-first.ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** Определить, какое приложение/сервис генерирует сетевой трафик, анализируя последовательности из 30 пакетов (`tcp_len_1`...`tcp_len_30`).  
**Зачем это нужно на практике:** В корпоративных сетях и прокси нужно автоматически классифицировать приложения (YouTube, Zoom, Telegram, Torrent и т.д.) без глубокого анализа содержимого пакетов (DPI). Достаточно паттернов размеров и направлений пакетов.  
**Ключевая логика пайплайна:** 
1. Загрузили огромные CSV → сжали типы данных до `int16`/`float16`.
2. Разделили длину пакета на **размер** и **направление** (отправка/получение), создав 3D-тензоры `(N, 30, 2)`.
3. Использовали **свёрточную нейросеть (Conv1D)**, которая "скользит" по последовательности пакетов и учится распознавать уникальные "отпечатки" приложений.
4. Обучили модель через 3-фолдовую кросс-валидацию, усреднили предсказания и избежали переполнения памяти GPU через чанкование.
5. Сформировали `submission.csv` с названиями приложений.

### 🔹 БЛОК 3: Кодирование целевых меток
🎯 **Задача блока:** Превратить названия приложений в целые числа для нейросети.  
📁 **Файлы/Данные:** Колонка `app_service` (строки: `"youtube"`, `"zoom"`, `"unknown"` и т.д.).

🔄 **Что происходит с данными:**

### 🔹 БЛОК 4: Препроцессинг и создание 3D-тензоров
🎯 **Задача блока:** Преобразовать плоскую таблицу в объёмные данные, понятные свёрточной сети.  
📁 **Файлы/Данные:** Матрица `30` колонок с длинами пакетов. Отрицательные значения = направление "сервер → клиент", положительные = "клиент → сервер".  
🛠 **Библиотеки:** `numpy` (`abs`, `sign`, `stack`).  
🔄 **Что происходит с данными:** 
1. `X / 1500.0` — нормализация. 1500 байт = стандартный MTU Ethernet. Делим, чтобы все значения были в диапазоне `[-1, 1]`.
2. `size = np.abs(X)` — оставляем только абсолютный размер пакета.
3. `direction = np.sign(X)` — оставляем только направление (`+1` или `-1`).
4. `np.stack([size, direction], axis=-1)` — склеиваем в тензор формы `(N, 30, 2)`. Теперь у нас 30 шагов (пакетов), на каждом шаге 2 признака (размер + направление).
5. `del train_df, test_df` + `gc.collect()` — сразу удаляем исходные таблицы, освобождая гигабайты памяти.  
🔜 **Переход:** Тензоры готовы, описываем архитектуру нейросети.

### 🔹 БЛОК 5: Архитектура модели (Conv1D)
🎯 **Задача блока:** Построить сеть, которая будет искать паттерны в последовательностях пакетов.  
📁 **Файлы/Данные:** Вход: `(batch, 30, 2)`. Выход: вероятности для каждого класса приложения.  
🛠 **Библиотеки:** `keras.layers` (Conv1D, BatchNormalization, GlobalAveragePooling1D, Dense, Dropout).  
🔄 **Что происходит с данными:** 
1. `Conv1D(64/128/256, kernel=3)` — "фильтры" скользят по 30 пакетам, выделяя локальные паттерны (например, "маленький запрос → большой ответ → пауза").
2. `BatchNormalization` — нормализует выходы слоёв, ускоряет обучение и стабилизирует градиенты.
3. `GlobalAveragePooling1D` — сжимает последовательность из 30 шагов в один вектор признаков, усредняя важную информацию.
4. `Dense(256) + Dropout(0.4)` / `Dense(128) + Dropout(0.3)` — классификатор. Dropout случайно "выключает" 30-40% нейронов на каждом шаге, чтобы сеть не запоминала шум, а учила общие правила.
5. `Dense(num_classes, softmax)` — выдаёт итоговые вероятности. `dtype='float32'` нужен для стабильного подсчёта потерь.  
🔜 **Переход:** Модель описана, но тестовый набор огромный. Пишем функцию предсказания частями.

### 🔹 БЛОК 6: Функция чанкованного предсказания
🎯 **Задача блока:** Предсказать классы для миллионов строк, не уронив GPU по памяти.  
📁 **Файлы/Данные:** `X_test` (огромный массив `float16`).  
🛠 **Библиотеки:** `model.predict()`, `gc.collect()`.  
🔄 **Что происходит с данными:**

- Предсказывает кусок → сохраняет вероятности → удаляет кусок из памяти → вызывает сборщик мусора.
- `np.vstack(preds)` собирает результаты обратно в один массив.  
🔜 **Переход:** Инструменты готовы, запускаем цикл обучения по фолдам.

### 🔹 БЛОК 7: Обучение и кросс-валидация
🎯 **Задача блока:** Обучить 3 модели на разных частях данных, получить стабильные предсказания.  
📁 **Файлы/Данные:** `X` (train), `y` (метки), `X_test`.  
🛠 **Библиотеки:** `StratifiedKFold(n_splits=3)`, `EarlyStopping`, `ReduceLROnPlateau`.  
🔄 **Что происходит с данными:** 
1. Данные делятся на 3 равные части с сохранением пропорций классов.
2. **Fold 1:** Train на 2/3, Valid на 1/3. Сохраняем `oof_preds` для валидационной части. Предсказываем `test_preds`.
3. `test_preds += predict / 3` — добавляем предсказания текущей модели к общему массиву, деля на 3. В конце цикла получится среднее арифметическое вероятностей трёх моделей (ансамбль).
4. `tf.keras.backend.clear_session()` + `gc.collect()` — полностью очищают граф TF и RAM после каждого фолда, чтобы следующий запуск был "чистым".  
🔜 **Переход:** Все 3 модели обучены, вероятности усреднены. Оцениваем качество и сохраняем ответ.

### 🎯 ОБЩАЯ ЦЕЛЬ & АРХИТЕКТУРА
**Задача:** По последовательности длин 30 TCP-пакетов классифицировать приложение/сервис (`app_service`).  
**Ключевая особенность:** Отказ от табличных моделей в пользу **1D-CNN**. Данные преобразуются в 2-канальный тензор `(N, 30, 2)`: канал 0 — абсолютный размер пакета, канал 1 — направление (`+1` outbound, `-1` inbound).  
**Метрика:** `Macro F1-score` (равноправие всех классов, включая редкие приложения).  
**Пайплайн:** Загрузка CSV → `LabelEncoder` → `float16` нормализация → 3-Fold CV с `EarlyStopping` + `ReduceLROnPlateau` → Chunked GPU inference → `submission.csv`.

### 🔹 РАЗБОР ПО ЭТАПАМ ВЫПОЛНЕНИЯ

#### 🔹 ЭТАП 1: Конфигурация & GPU-безопасность
- `tf.config.experimental.set_memory_growth(gpu, True)` отключает аллокацию ~95% VRAM при старте TF. Память выделяется динамически по мере загрузки тензоров. Критично для Kaggle-инстансов с 16 ГБ P100, где системные процессы уже занимают ~1–2 ГБ.
- `np.random.seed(42)`, `tf.random.set_seed(42)` фиксируют генераторы для воспроизводимости сплитов и Dropout-масок.

#### 🔹 ЭТАП 2: Загрузка данных & `LabelEncoder`
- `dtype_dict = {f'tcp_len{i}': np.int16 for i in range(1, 31)}` сразу читает CSV в 2-байтном формате. Экономит ~50% RAM на этапе `pd.read_csv`.
- `LabelEncoder` мапит строковые имена приложений в `[0, 1, ..., C-1]`. Сохраняет `le.classes_` для обратной трансформации в submission.

#### 🔹 ЭТАП 3: `preprocess()` — Векторная подготовка тензоров
- `X = df[packet_cols].values.astype(np.float16)` → массив `(N, 30)`.
- `X = X / 1500.0` → нормализация по MTU (1500 байт). Диапазон значений становится `[0, 1]`.
- `size = np.abs(X)`, `direction = np.sign(X)` → разделение на амплитуду и знак направления трафика.
- `X = np.stack([size, direction], axis=-1).astype(np.float16)` → финальная форма `(N, 30, 2)`. `float16` экономит VRAM и пропускную способность шины PCIe/CUDA.

#### 🔹 ЭТАП 4: Архитектура модели `create_model()`
- `Conv1D(64, 3, padding='same')` → скользящее окно размера 3 по оси времени (30 пакетов). `padding='same'` сохраняет длину 30.
- `BatchNormalization()` → нормализует активации по батчу перед ReLU.
- Повторяется 3 раза с ростом фильтров: `64 → 128 → 256`.
- `GlobalAveragePooling1D()` → усредняет по временной оси `(30, 256) → (256,)`. Заменяет `Flatten() + Dense`, сокращая параметры в 30× и добавляя инвариантность к сдвигу паттернов.
- `Dense(256) → Dropout(0.4) → Dense(128) → Dropout(0.3) → Dense(num_classes, softmax, dtype='float32')`.
- `optimizer=Adam(1e-3)`, `loss='sparse_categorical_crossentropy'`.

#### 🔹 ЭТАП 5: Цикл обучения (3-Fold CV)
- `StratifiedKFold(n_splits=3)` сохраняет распределение классов.
- Коллбэки: `EarlyStopping(patience=2, restore_best_weights=True)`, `ReduceLROnPlateau(patience=1)`.
- OOF-прогнозы заполняются в `oof_preds[val_idx]`.
- Тестовые прогнозы усредняются: `test_preds += predict_in_chunks(...) / N_SPLITS`.
- `tf.keras.backend.clear_session()` очищает TF-граф и освобождает VRAM между фолдами.

#### 🔹 ЭТАП 6: Chunked Inference `predict_in_chunks()`
- Разбивает `X_test` на чанки по 100 000 строк.
- Вызывает `model.predict(chunk, batch_size=512, verbose=0)`.
- `del chunk, p; gc.collect()` принудительно сбрасывает ссылки и запускает сборщик мусора Python/CUDA.
- Возвращает `np.vstack(preds)`. Гарантирует отсутствие `CUDA_ERROR_OUT_OF_MEMORY`.

#### 🔹 ЭТАП 7: Скоринг & Submission
- `oof_preds.argmax(axis=1)` → предсказанные классы.
- `f1_score(y, oof_labels, average='macro')` → финальная метрика.
- `test_preds.argmax(axis=1) → le.inverse_transform()` → маппинг обратно в строки. Сохранение `submission.csv`.

### 🧠 ВНУТРЕННЯЯ МЕХАНИКА БИБЛИОТЕК (DEEP DIVE)

| Компонент | Внутренняя механика | Почему это важно в проекте |
|:---|:---|:---|
| `tf.config.experimental.set_memory_growth` | Переключает CUDA-аллокатор с `cudaMalloc` (жадный) на `cudaMallocAsync`/`cuDF` (ленивый). TF запрашивает память только при создании тензоров. | Без этого TF займёт ~14 ГБ VRAM на старте, оставив <2 ГБ под вычисления. На P100 это мгновенный OOM. |
| `numpy` `float16` + `/1500` | Векторизованные операции используют SIMD (AVX2/AVX-512 на CPU). `float16` хранит 10 бит мантиссы, 5 бит экспоненты. Деление на скаляр не требует broadcast-копирования. | Сокращает объём данных, передаваемых по шине PCI-e в GPU, в 2×. Ускоряет загрузку тензоров в VRAM. |
| `Conv1D(kernel_size=3, padding='same')` | Алгоритм свёртки: `output[t] = Σ_{k=0}^{2} W[k] * input[t+k-1]`. `padding='same'` добавляет по 1 нулю слева и справа, чтобы выходная длина совпадала с входной. | Ловит локальные паттерны трафика (например, `SYN → ACK → DATA`). 3 пакета — минимальный контекст для TCP-рукопожатий. |
| `BatchNormalization` | Вычисляет `μ = mean(x)`, `σ² = var(x)` по оси `(batch, sequence)`. Применяет `x' = γ*(x-μ)/√(σ²+ε) + β`. Во время inference использует скользящие средние (`momentum=0.99`). | Стабилизирует градиенты, позволяет использовать `Adam(1e-3)` без взрывов. Компенсирует сдвиг распределений между фолдами. |
| `GlobalAveragePooling1D` | `output[c] = (1/L) * Σ_{t=1}^{L} feature_map[t, c]`. Линейная операция без обучаемых весов. | Заменяет `Flatten() + Dense(256*30)`. Сокращает параметры с ~195k до ~65k, добавляет устойчивость к сдвигу паттернов во времени. |
| `Dropout(0.4/0.3)` | Во время training случайно зануляет 40%/30% нейронов. Во время inference оставшиеся веса масштабируются на `1/(1-p)` (Inverted Dropout). | Предотвращает ко-адаптацию фильтров CNN. Заставляет сеть учить распределённые признаки, а не запоминать конкретные позиции пакетов. |
| `Adam(learning_rate=1e-3)` | Поддерживает EMA градиентов `m_t = β₁·m_{t-1} + (1-β₁)·g_t` и EMA квадратов `v_t = β₂·v_{t-1} + (1-β₂)·g_t²`. Применяет bias correction и шаг `θ ← θ - α·m̂/(√v̂+ε)`. | Адаптирует LR для каждого параметра. Быстро сходится на несбалансированных последовательностях. |
| `sparse_categorical_crossentropy` | Вычисляет `Loss = -log( softmax(z)[y] )`. Ожидает целочисленные метки `y ∈ [0, C-1]`. Не требует `to_categorical()`. | Экономит RAM/VRAM в 20–50× по сравнению с one-hot векторами для 10+ классов. |
| `EarlyStopping(patience=2)` | Мониторит `val_loss`. Если `val_loss[t] > min_val_loss` в течение 2 эпох, останавливает обучение. `restore_best_weights=True` откатывает веса к эпохе с минимальным `val_loss`. | Предотвращает переобучение на 8 эпохах. Типично лучшая модель достигается на эпохах 5–7. |
| `ReduceLROnPlateau(patience=1)` | Если `val_loss` не улучшается 1 эпоху, умножает LR на `factor=0.1` (default). | Позволяет модели "доучиться" в узком бассейне локального минимума после быстрого спуска. |
| `tf.keras.backend.clear_session()` | Сбрасывает глобальный TF-граф, удаляет ссылки на слои, очищает кэш операций, вызывает `cudaDeviceSynchronize()`. | Без этого VRAM будет накапливаться между фолдами (leak). На 3-м фолде P100 упадёт с `CUDA_ERROR_OUT_OF_MEMORY`. |
| Chunked Inference | Разбивает тензор на slices `[i:i+CHUNK_SIZE]`. Каждый slice проходит forward pass. `gc.collect()` освобождает Python-объекты, `del` удаляет CUDA-тензоры. | 8.2M строк × float16 × 2 канала ≈ 330 МБ входных данных. Прямой `predict()` создаст временные тензоры активаций >4 ГБ. Чанкование держит peak VRAM <10 ГБ. |

### ⚠️ КРИТИЧЕСКИЕ НЮАНСЫ & ТОЧКИ РОСТА

1. **`float16` на Tesla P100**  
   P100 имеет **ограниченную поддержку FP16** (нет Tensor Cores). Вычисления в `float16` выполняются на CUDA-ядрах с точностью FP32, но данные всё равно хранятся в FP16. Выигрыш только в памяти/пропускной способности, не в FLOPS.  
   ✅ **Оптимизация:** На V100/A100/T4 включить `tf.keras.mixed_precision.set_global_policy('mixed_float16')` для нативного использования Tensor Cores.

2. **`ReduceLROnPlateau(patience=1)` слишком агрессивен**  
   При шуме в валидационном loss LR может упасть до `1e-4` уже на 3-й эпохе, остановив обучение слишком рано.  
   ✅ **Фикс:** `patience=2` или `factor=0.5`, либо переход на `CosineDecay` scheduler.

3. **Отсутствие Data Augmentation**  
   Пакетные последовательности можно аугментировать: добавление гауссова шума к `tcp_len`, случайный сдвиг окна (`TimeShift`), `TemporalDropout` на входе.  
   ✅ **Улучшение:** Поднимет Robustness к вариациям MTU и retransmissions.

4. **`macro` F1 vs реальное распределение**  
   Если 80% трафика приходится на 3 приложения, `macro F1` будет жёстко штрафовать ошибки на редких классах, но игнорировать точность на частых. Для продакшена часто лучше `weighted F1` или кастомная метрика с бизнес-весами.

5. **`padding='same'` на длине 30**  
   Добавляет 1 нулевой пакет слева и справа. Для TCP это эквивалентно "пустому" пакету, который может исказить первые/последние свёрточные фильтры.  
   ✅ **Альтернатива:** `padding='valid'` + `GlobalAveragePooling1D` (длина станет 28, но без артефактов границ).

6. **Chunk Size 100k — эмпирический**  
   Не адаптивен под размер батча и VRAM.  
   ✅ **Фикс:** `CHUNK_SIZE = int(tf.config.experimental.get_memory_info('GPU:0')['current'] * 0.6 / (model.count_params() * 4))`.
