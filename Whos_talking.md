# 📡 Who's Talking — РАЗБОР ВСЕХ БЛОКОВ (wtf-whos-talking-first.ipynb)

### 🎯 ОБЩАЯ ЦЕЛЬ ПРОЕКТА
**Задача:** Определить, какое приложение/сервис генерирует сетевой трафик, анализируя последовательности из 30 пакетов (`tcp_len_1`...`tcp_len_30`).  
**Зачем это нужно на практике:** В корпоративных сетях и прокси нужно автоматически классифицировать приложения (YouTube, Zoom, Telegram, Torrent и т.д.) без глубокого анализа содержимого пакетов (DPI). Достаточно паттернов размеров и направлений пакетов.  
**Ключевая логика пайплайна:** 
1. Загрузили огромные CSV → сжали типы данных до `int16`/`float16`.
2. Разделили длину пакета на **размер** и **направление** (отправка/получение), создав 3D-тензоры `(N, 30, 2)`.
3. Использовали **свёрточную нейросеть (Conv1D)**, которая "скользит" по последовательности пакетов и учится распознавать уникальные "отпечатки" приложений.
4. Обучили модель через 3-фолдовую кросс-валидацию, усреднили предсказания и избежали переполнения памяти GPU через чанкование.
5. Сформировали `submission.csv` с названиями приложений.

🎯 **Задача блока:** Подключить библиотеки, зафиксировать случайность и безопасно настроить работу с видеокартой.

🛠 **Библиотеки:** 
- `tensorflow` / `keras` — построение и обучение нейросетей.
- `numpy` / `pandas` — работа с массивами и таблицами.
- `sklearn` — кодирование меток, разделение на фолды, расчёт F1.
🔄 **Что происходит с данными:** 
- `tf.config.experimental.set_memory_growth(gpu, True)` — запрещает TF захватить всю видеопамять сразу. Выделяет её по мере необходимости, чтобы ноутбук не падал с OOM (Out Of Memory).
- Фиксируются `SEED=42`, `BATCH_SIZE=512`, `EPOCHS=8`, `CHUNK_SIZE=100000`.  
🔜 **Переход:** Среда готова, загружаем сырые данные.

### 🔹 БЛОК 2: Загрузка данных
🎯 **Задача блока:** Прочитать `train.csv` и `test.csv`, экономя оперативную память.  
📁 **Файлы/Данные:** CSV-файлы с миллионами строк. Колонки `tcp_len_1`...`tcp_len_30` содержат длины пакетов в байтах. Цель: `app_service`.  
🛠 **Библиотеки:** `pd.read_csv()` с `dtype=dtype_dict`.  
🔄 **Что происходит с данными:** 
- Указываем `np.int16` для колонок пакетов. Обычно pandas читает их как `int64` (8 байт на число), а мы сжимаем до 2 байт. Экономим ~75% RAM.
- Выделяем списки колонок `packet_cols` и `target_col`.  
🔜 **Переход:** Текст в целевой колонке нужно перевести в числа.

### 🔹 БЛОК 3: Кодирование целевых меток
🎯 **Задача блока:** Превратить названия приложений в целые числа для нейросети.  
📁 **Файлы/Данные:** Колонка `app_service` (строки: `"youtube"`, `"zoom"`, `"unknown"` и т.д.).  
🛠 **Библиотеки:** `LabelEncoder`.  
🔄 **Что происходит с данными:** 
- `le.fit_transform()` сканирует все уникальные названия, сортирует их и назначает каждому номер: `0, 1, 2...`
- `num_classes` запоминает общее количество приложений.
- В `y` теперь лежат только числа, а обратное преобразование `le.inverse_transform()` сохранено на потом.  
🔜 **Переход:** Числа готовы, формируем входные тензоры для CNN.

---

### 🔹 БЛОК 4: Препроцессинг и создание 3D-тензоров
🎯 **Задача блока:** Преобразовать плоскую таблицу в объёмные данные, понятные свёрточной сети.  
📁 **Файлы/Данные:** Матрица `30` колонок с длинами пакетов. Отрицательные значения = направление "сервер → клиент", положительные = "клиент → сервер".  
🛠 **Библиотеки:** `numpy` (`abs`, `sign`, `stack`).  
🔄 **Что происходит с данными:** 
1. `X / 1500.0` — нормализация. 1500 байт = стандартный MTU Ethernet. Делим, чтобы все значения были в диапазоне `[-1, 1]`.
2. `size = np.abs(X)` — оставляем только абсолютный размер пакета.
3. `direction = np.sign(X)` — оставляем только направление (`+1` или `-1`).
4. `np.stack([size, direction], axis=-1)` — склеиваем в тензор формы `(N, 30, 2)`. Теперь у нас 30 шагов (пакетов), на каждом шаге 2 признака (размер + направление).
5. `del train_df, test_df` + `gc.collect()` — сразу удаляем исходные таблицы, освобождая гигабайты памяти.  
🔜 **Переход:** Тензоры готовы, описываем архитектуру нейросети.

---

### 🔹 БЛОК 5: Архитектура модели (Conv1D)
🎯 **Задача блока:** Построить сеть, которая будет искать паттерны в последовательностях пакетов.  
📁 **Файлы/Данные:** Вход: `(batch, 30, 2)`. Выход: вероятности для каждого класса приложения.  
🛠 **Библиотеки:** `keras.layers` (Conv1D, BatchNormalization, GlobalAveragePooling1D, Dense, Dropout).  
🔄 **Что происходит с данными:** 
1. `Conv1D(64/128/256, kernel=3)` — "фильтры" скользят по 30 пакетам, выделяя локальные паттерны (например, "маленький запрос → большой ответ → пауза").
2. `BatchNormalization` — нормализует выходы слоёв, ускоряет обучение и стабилизирует градиенты.
3. `GlobalAveragePooling1D` — сжимает последовательность из 30 шагов в один вектор признаков, усредняя важную информацию.
4. `Dense(256) + Dropout(0.4)` / `Dense(128) + Dropout(0.3)` — классификатор. Dropout случайно "выключает" 30-40% нейронов на каждом шаге, чтобы сеть не запоминала шум, а учила общие правила.
5. `Dense(num_classes, softmax)` — выдаёт итоговые вероятности. `dtype='float32'` нужен для стабильного подсчёта потерь.  
🔜 **Переход:** Модель описана, но тестовый набор огромный. Пишем функцию предсказания частями.

---

### 🔹 БЛОК 6: Функция чанкованного предсказания
🎯 **Задача блока:** Предсказать классы для миллионов строк, не уронив GPU по памяти.  
📁 **Файлы/Данные:** `X_test` (огромный массив `float16`).  
🛠 **Библиотеки:** `model.predict()`, `gc.collect()`.  
🔄 **Что происходит с данными:** 
- Цикл `for i in range(0, n, CHUNK_SIZE)` режет массив на куски по 100 000 строк.
- Предсказывает кусок → сохраняет вероятности → удаляет кусок из памяти → вызывает сборщик мусора.
- `np.vstack(preds)` собирает результаты обратно в один массив.  
🔜 **Переход:** Инструменты готовы, запускаем цикл обучения по фолдам.

---

### 🔹 БЛОК 7: Обучение и кросс-валидация
🎯 **Задача блока:** Обучить 3 модели на разных частях данных, получить стабильные предсказания.  
📁 **Файлы/Данные:** `X` (train), `y` (метки), `X_test`.  
🛠 **Библиотеки:** `StratifiedKFold(n_splits=3)`, `EarlyStopping`, `ReduceLROnPlateau`.  
🔄 **Что происходит с данными:** 
1. Данные делятся на 3 равные части с сохранением пропорций классов.
2. **Fold 1:** Train на 2/3, Valid на 1/3. Сохраняем `oof_preds` для валидационной части. Предсказываем `test_preds`.
3. `test_preds += predict / 3` — добавляем предсказания текущей модели к общему массиву, деля на 3. В конце цикла получится среднее арифметическое вероятностей трёх моделей (ансамбль).
4. `tf.keras.backend.clear_session()` + `gc.collect()` — полностью очищают граф TF и RAM после каждого фолда, чтобы следующий запуск был "чистым".  
🔜 **Переход:** Все 3 модели обучены, вероятности усреднены. Оцениваем качество и сохраняем ответ.

### 🔹 БЛОК 8: Оценка и сохранение submission
🎯 **Задача блока:** Перевести вероятности обратно в названия приложений и выгрузить файл.  
📁 **Файлы/Данные:** `oof_preds`, `test_preds` (массивы вероятностей).  
🛠 **Библиотеки:** `f1_score`, `pd.DataFrame`, `.to_csv()`.  
🔄 **Что происходит с данными:** 
- `argmax(axis=1)` — для каждой строки берёт индекс класса с максимальной вероятностью.
- `f1_score(y, oof_labels, average='macro')` — считает средний F1 по всем классам (равноценно относится и к популярным, и к редким приложениям).
- `le.inverse_transform(test_labels)` — превращает числа `0, 5, 12...` обратно в `"youtube"`, `"discord"`, `"netflix"`.
- Формируется `submission.csv` и сохраняется.  
🔜 **Переход:** Работа завершена.
